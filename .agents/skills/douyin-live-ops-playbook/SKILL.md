## Codex 执行适配（2026-11-08）

本段限定下方原方法论在当前项目中的适用范围；保留原正文以便追溯，不把历史政策或阈值当作实时事实。

- 先运行本 Skill 的 `scripts/resolve_project.py`，从 Skill 所在位置向上找到同时含 `runtime-agents/`、`docs/`、`templates/`、`data-pipeline/` 的项目根目录。正文内 `docs/`、`templates/`、`research/`、`data-pipeline/` 等路径均相对于该根目录，不是当前工作目录或 Skill 目录。可给解析脚本传入正文路径取得绝对路径；找不到资源须报告，不能臆造。
- 开始对应任务前读取下方引用的岗位知识、模板与数据渠道说明；需要的项目资源保持在根目录，共享资源不复制成容易失真的独立知识版本。
- 原“零网络／零凭证／完全跑通”等叙述，只能用作冻结快照离线复验的历史上下文。离线复验保持零网络门禁；实际市场研究按用户已授予的在线范围执行，工具和凭证是否可用须现场验证。不得把静态 Skill 安装或离线成功写成真实业务能力全部验证。
- 下方平台税费、评分门槛、履约方式、准入及活动政策均可能过期。实际经营决策前按当前站点官方来源复核日期、适用类目和履约模式；未复核明确待确认。JD 频次、历史比例仅是研究样本。
- 用户当前授权 Just One 与 FastMoss 的在线选品测试；使用授权免费额度，额外付费、外部联系、下单或投放须有相应用户授权。既有授权不重复询问。密钥仅从受保护凭证读取，不写入 Skill、提示词、仓库或报告。
- 使用任务给定数据与可追溯来源交付原岗位成果，缺经营数据则列缺口或用明确标注的演示输入，不能编造成交、利润、转化、供应商或验证记录。
- 直播品牌背书/真伪候选复核时，先读 [品牌一致静默规则v2](../../../docs/直播品牌背书视觉一致性静默规则-v2.md)，再用 `scripts/live_brand_visual_silence_v2.py` 后处理；品牌一致时仅相关品牌对应/授权提醒静默，不逐一索证，授权状态内部留存；品牌不一致、画面不足和其他独立风险保留。平台/站点规则与价审门禁仍分别核对。
### 排品底表、总量复核与当前商品事实

- 排品主摘要、逐款台账、主播与场控话术（含过渡句）、库存说明和下游交接共用同一份有来源的结构底表；保留已给的平台、站点、商品ID/SKU、规格修订、计划数量、销售单位及事实来源。变更排品后从当前底表重新派生这些输出，不在摘要或交接中另猜一个总量。
- 总规格订单数/销售包数量先说明本场计数口径，再对同单位的计划行求和；实物件数另按各行计划数量乘已证实的每销售单位件数或套装因子后汇总。两种数量分列，不混作真实去重订单数；按唯一计划行或分配标识累计；同一分配仅因引用或展示重复而不再加计，返场有独立新增分配必须计入；无法判断两行是否同一分配时说明不确定，不因同SKU自动去重。换算所需单位或因子缺失时，该实物合计保持未知，已有规格数量可分别保留。
- 输出前对底表逐项复算计划数量、收入与贡献，保留所用行、单位和算式，再交叉核对主摘要、台账、库存、话术和交接。发现汇总与逐项不一致，先修正派生结果再交付；需要计算时用受支持的本地计算路径核对，写有规则或列出算式本身不等于算术已正确。
- 独立案件以当前案已提供或明确获准本案引用、且来源和商品身份已绑定的事实为界。别题同名SKU、旧模板或记忆不能自动补入本案的规格、材质、认证、数量或承诺；已给商品ID/SKU和规格修订逐项核对，未给的身份或修订也不臆造。真实连续业务可复用有来源、在适用期内、身份与修订明确且获准共享的事实卡，不把所有历史事实一律作废。
- 未给或null的具体属性在商品简称、过渡口播、完整脚本、字幕及交接中同样不得悄悄补齐。只略去该未知属性或用清楚的条件表达，并列补证责任和所需材料；可继续使用有出处的安全讲品、排练草稿与独立替代建议，不因一项未知笼统拒绝整套正常方案。
- 品牌视觉一致仍按 `docs/直播品牌背书视觉一致性静默规则-v2.md` 处理：仅相关品牌对应/授权提醒静默，不据此证明法律授权或全部属性真实，其他独立风险保留。本段不放宽既有价审、权限、退款/成熟窗口、平台站点及口播纪律。

# 抖音直播运营方法论

本 Skill 面向抖音直播场次操盘。**TikTok 侧的本地化话术、COD 预期管理、联盟内容导流在抖音不存在，不可套用。**

---

## 1. 岗位定义与考核指标

### 岗位定位
抖系直播链路的**结果承接方**，核心能力是**人货场匹配**。层级：

| 层级 | 职责 | 能力要求 |
|---|---|---|
| 运营专员/中控 | 执行单场、控后台、促气氛 | 1 年以上即可，部分接受应届生 |
| **直播运营** | **负责单账号数据与话术** | **2 年以上为主流门槛** |
| 直播运营主管/经理 | 货盘节奏、投流预算、主播团队 | 3-5 年起步 |
| 直播负责人/项目经理 | GMV 利润人效、搭体系带团队 | 5-10 年 + 团队管理经验 |

**本岗位按"直播运营"层要求：能独立负责一个账号的场次与话术。**

### 考核指标

| 指标 | 说明 | 频次 |
|---|---|---|
| **数据分析** | 流量漏斗、用户画像、商品转化拆解 | 24/26 |
| **主播/助播/中控/场控协作** | | 19/26 |
| **SOP 与话术库沉淀** | 直播 SOP、话术库、爆款模板 | 19/26 |
| **节奏与现场控场** | 时段节奏、互动引导、情绪调动 | 15/26 |
| **GMV 结果承接** | | 15/26 |
| **活动机制与权益设计** | 福袋/秒杀/抽奖/券发放/大促报名 | 15/26 |
| **付费流量投放协同** | 千川/随心推/DOU+ 计划搭建与预算 | 14/26 |
| **排品/货盘** | 选品/排品、货盘分层、定价 | 14/26 |
| **复盘报告** | 日/周/月 | 16/26 |
| ROI / 转化率 / UV 价值 | | 9/26 各 |
| 短视频引流与自然流量优化 | 引流脚本、直播间标签、AB 链管控、口碑分维护 | — |
| 竞品与行业趋势跟踪 | | 8/26 |

### 硬性任职门槛（26 篇真实 JD 统计）
- **学历**：大专及以上为主流起点（大量主管岗写"大专"），本科为品牌方与负责人岗主流；**统招本科在品牌方/上市公司被明确点名**
- **年限**：中控/场控 1 年以上即可（部分接受应届生）；直播运营 2 年以上为主流；主管 3-5 年；负责人 5-10 年 + 团队管理
- **业绩门槛（10/26 篇明确写 0-1 起盘）**：「曾主导单账号月出库流水达 100 万元及以上」「有月销 1000W+ 直播间实操案例，完整经历至少 1 个美妆品牌自播号 0-1 搭建过程者优先」「独立操盘直播间，单场 GMV 50W+ 或月体量 500W+」「具备完整的直播间增量操盘经验（1-10），有可落地、可追溯的 GMV 业绩案例」
- **后台工具**：抖店后台、巨量百应、精选联盟、直播伴侣、抖音罗盘
- **投放工具**：**巨量千川、随心推、DOU+ 的独立投流及预算管理能力**（捷美瑞、闪极、维发明确要求）
- **数据工具**：Excel/数据透视表/PPT/Word（明确列为主机工具门槛）；蝉妈妈/抖查查做竞品分析
- **硬件与现场**：会调试摄像头、灯光、麦克风、推流与网络，**能快速排查卡顿断流**
- **视觉与素材**：PS、AI 优先
- **数据诊断方法论**：丸美生物点名"流量峰值捕捉、转粉率提升技巧"，要求能独立完成含**排品策略、过款动线、憋单话术**的直播 SOP 文档
- **软性**：抗压与适应直播行业节奏（16/26 篇）、快速应变与临场反应、多项目并行

## 2. 人货场匹配模型

### 2.1 人
主播、助播、中控、场控的分工与配合。JD 明确要求你具备**主播招募面试培训带教、排班、话术训练、分级培养、绩效与激励机制**的设计能力——**直播运营不只是"用"主播，还要"造"主播。**

### 2.2 货
排品/货盘分层/定价/上新对接/库存盘点/价格体系/规避超卖缺货。
- 五种商品角色（见 §3）
- 货盘组合：引流款 + 利润款 + 爆款 + 新品组合

### 2.3 场
场景搭建、时段节奏、互动引导、情绪调动、突发处置。

**匹配诊断**：人（主播状态与话术）× 货（过款结构与价格）× 场（节奏与流量）三者任一不匹配，都会表现为转化率低。**先判断是哪一项不匹配，再决定改什么。**

## 3. 五种商品角色排品法

用 `templates/直播运营/直播排品表.md`。

| 角色 | 目的 | 典型设置 | 场次数量 |
|---|---|---|---|
| **引流款** | 拉停留、破冰成交 | 低门槛、限量秒杀 | 1 |
| **利润款** | 承担出量、毛利最高 | 核心讲解对象 | 1-2 |
| **爆款** | 拉 GMV 峰值 | 引流最大化或引流效率最高 | 1 |
| **形象款** | 品牌调性、承接高客单 | 高客单、讲品牌 | 0-1 |
| **清尾款** | 清库存 | 不承担 GMV 但占坑位 | 0-1 |

**排品顺序 = 节奏设计 = GMV 结构。** 顺序错了，后面所有话术都白费。

## 4. 七环节话术结构

用 `templates/直播运营/直播脚本框架.md`。每款商品按七环节讲：

| 环节 | 要点 |
|---|---|
| 痛点引入 | |
| 卖点展开 | **只讲 1 个核心卖点** |
| 演示/实测 | |
| 信任建立 | 资质、销量、评价、达人背书 |
| 价格锚点与优惠 | |
| 异议处理 | **最容易被忽略但最影响转化** |
| 促单指令 | 明确行动指令 + 紧迫感 |

### 抖音必答异议
- 退换政策
- **仅退款如何处理**（抖音特有）
- 发货时效
- 品质证明

### 憋单与逼单
JD 明确点名"憋单话术""逼单话术"为高频要求。憋单 = 制造期待与稀缺（限时限量），逼单 = 明确行动指令。**两者都必须真实**——虚假库存、虚假限时是违规。

## 5. 分时段节奏表

| 时段 | 内容 | 目的 | 关键动作 |
|---|---|---|---|
| 0-3 分 | 开场福利/憋单 | 拉停留、聚人气 | |
| 3-10 分 | 引流款 | 破冰成交、留人 | |
| 10-25 分 | 利润款 | 出量 | |
| 25-40 分 | 爆款 + 福利款 | 拉 GMV、逼单 | |
| 40-55 分 | 福利款循环 | 拉时长、承接投流 | |
| 55-60 分 | 爆款返场 | 冲量 | |
| 60 分+ | 循环或下场 | | |

**投流节奏必须与过款节奏对齐**，不是单纯抢量。全域推广下以商品整体支付 ROI 为优化目标。

## 6. 场次复盘规范

用 `templates/直播运营/直播复盘表.md`。**场后 24 小时内完成**（隔天数据会失真）。

### 6.1 核心指标
场观、峰值在线、平均在线、平均停留时长、互动率、商品点击率、点击→下单转化率、订单数、GPM（千次观看成交额）、GMV、投流消耗、**表面 ROI**、退款率、**净 ROI**、**净利**。

**净 ROI 必须扣退款。** 抖音"仅退款"让表面 ROI 失真。

### 6.2 逐款问题标注（必须归类，不只说"卖得不好"）
讲解不清 / 卖点弱 / 价格无优势 / 库存不足 / 素材缺失 / 流量不足 / 评论区质疑未处理 / 履约疑虑。

### 6.3 时段拆解
每个时段的在线、互动、点击、转化、GMV，并给结论（最佳时段、最差时段及原因）。

## 7. 突发处置规范

JD 明确列出必处置场景：

| 场景 | 处置方向 |
|---|---|
| **违规警告** | 立即停用相关话术，检查禁用词，调整后续讲解 |
| **舆情** | 统一口径，必要时转私域沟通，暂停争议商品讲解 |
| **断播/卡顿** | 快速排查推流与网络（JD 要求会调试设备）；启用备用网络；场控维持氛围 |
| **超卖** | 立即下架/改价，公告处理方案，主动补偿 |
| **库存不足** | 切换替代款，调整排品 |
| **投流超预算** | 降预算或暂停低效计划 |
| **退货率飙升** | 立即调整预期管理话术，补充尺码对照 |

## 8. 常见错误与雷区

| 错误 | 后果 | 正确做法 |
|---|---|---|
| **排品无角色区分** | 全场没有节奏，转化靠运气 | 五种角色清晰设置 |
| **卖点讲三个以上** | 用户记不住，无购买理由 | 一款只打 1 个核心卖点 |
| **不做异议处理** | 用户在评论区质疑就流失 | 抖音必答四项异议 |
| **只看表面 ROI** | 仅退款吃掉利润，误判场次好坏 | 用扣退款后的净 ROI |
| **投流与过款脱节** | 预算浪费在低转化时段 | 按过款节奏配计划 |
| **虚假憋单/虚假限时** | 违规 | 稀缺机制必须真实 |
| **复盘隔天做** | 数据失真，决策错 | 24 小时内完成 |
| **逐款问题不归类** | 复盘无行动指向 | 按八类归类 |
| **不沉淀话术库与 SOP** | 每次从零开始 | 持续更新，含排品策略/过款动线/憋单话术 |
| **只盯头部达人** | 与大盘结构不符 | 中小达人贡献超 85% |
| **忽视短视频引流协同** | 自然流量占比低 | 与编导对齐素材投喂 |
| **无突发预案** | 出事即乱 | 违规/舆情/断播/超卖各有处置 |

## 10. 数据与规则的时效性规范

- **平台规则、审核规范、违规口径**：变动频繁，标注来源与时点。
- **大盘结构数据（433、店播占比等）**：标注来源与年份，不同机构统计口径有差异。
- **数据通道权威源**是项目 `docs/knowledge/data-channel.md`；取数走项目 `data-pipeline/` 下的采集器。**抖音侧零凭据通道已完全跑通**：热榜（`douyin_public.py`）+ 推荐流/话题真实体量/创作者画像/作品详情/评论（`douyin_feed.py`，推荐流自举，不需要种子 ID、不需要登录、不需要分享链接）。TikTok 侧采集器代码就绪，需 API token。外部数据只用于趋势与竞品判断，**经营口径（结算/真实退货/实收）必须来自店铺后台**。
