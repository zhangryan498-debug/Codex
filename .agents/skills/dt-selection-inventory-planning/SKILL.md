# 选品、库存与资金规划

交付可复核的决策草案，说明哪些已算清、哪些受条件限制、下一步补什么。选品证据、库存覆盖和资金可负担性分别判断。所有交付固定写明 `execution_authorized=false`、`purchase_execution_authorized=false`、`pricing_execution_authorized=false`、`release_status=not_authorized`；计算完整也不构成采购、定价、上架或投放授权。

## 使用与边界

- 本 Skill 补充原选品岗位，不复制或替代原岗位、采集器、利润表与价格门禁。无新运行脚本、无外部工具依赖。只使用任务提供或当前授权范围内的资料；历史在线授权、旧命令和上游教程不扩展本轮权限。
- `docs/`、`templates/`、`runtime-agents/`、`.agents/` 均相对D&T项目根目录。可从本 Skill 位置向上核对同时存在 `runtime-agents/`、`docs/`、`templates/`、`data-pipeline/` 的目录；找不到时报告资源缺口，继续处理可独立计算的任务输入。
- 执行选品评估时读 [选品证据](references/selection-evidence.md)；执行库存、预算或资金规划时读 [库存与资金](references/stock-capital.md)。涉及两者时都读。方法取舍与许可见 [来源](references/provenance.md)。
- 真正执行对应原岗位任务时，再读相应 `.agents/skills/douyin-selection-playbook/SKILL.md` 或 `.agents/skills/tiktok-selection-playbook/SKILL.md` 及所需模板；当前数据口径优先于旧文中的固定阈值、费率和历史能力声明。纯合成规划可按本 Skill 与明确输入完成，不以缺实盘数据一律拒绝。

## 共同输入纪律

先锁定平台、站点、商品ID、SKU/变体、仓库、评估时点与时区、规划截止日、数量单位、币种和需求口径。抖音为CN单站；TikTok按目标站点独立分析。

每个关键值保留原值/类型、来源及日期、有效期或适用窗口、单位、状态：`已确认值（含明确0）/未知/过期/冲突/不适用`。不适用要有理由；缺省、空串和未知不能变成0。明确合成值标为“给定情景”，不冒充观察或预测。来源有冲突时先核口径与权威性，保留异值及取舍；未消解的关键值不用于确定性结论，允许分支情景。

件、箱、套、公斤不直接相减或相乘。换算必须有对应SKU、包装层级与生效日期的依据，且同步换算成本、MOQ、库存和需求。先修单位再算；无法修正的分开列示。

## 执行与交付

1. **确定可算范围**：按用户任务选择证据比较、库存覆盖、补货或资金规划，不强制补齐无关模块。列出事实、假设与阻断项。
2. **选品先核硬门禁**：法规与资质、供应商匹配和履约、利润证据及关键数据状态分别记为“支持/失败/待核”。已有失败不能被高总分抵消；待核不能写通过。保留需求、竞争、退货、物流、供应链、利润分维证据。无获准评分模型时直接比较，不凑综合分。
3. **库存按时间核**：先算可用现货，再逐批判断在途能否在需要前成为可售库存。给目标覆盖量、原始缺口、MOQ约束量；把到货前缺货与期末覆盖分开说明。
4. **资金独立核**：补货量乘同单位到仓成本，加未被包含的采购支出；列币种分别小计、未知项及完整性。完整成本与有效汇率支持后才判断完整预算可负担性。MOQ向上、预算内数量向下处理，缩量后重算覆盖缺口。
5. **形成待审交接**：按SKU给出推荐/待补证/暂缓及依据，附输入、公式与未舍入中间数、取整、时间线、资金明细、预算差额、未解决项和责任岗位。缺资料仅挂起依赖该资料的结论，交付其余已支持结果。

结果至少区分：`plan_status=完整情景规划/部分规划/关键输入待核`；选品硬门禁状态；当前可用现货与在途抵扣依据；到货前缺口；目标量/缺口/MOQ量/预算内量；`known_subtotal` 与 `complete_cost`（未知则明确未知）；币种与FX适用期；三项执行授权均为false。仅有选品任务时不强填库存数字，反之亦然。

需要跨品牌、渠道或多岗取舍时，交接 `.agents/skills/dt-brand-channel-governance/SKILL.md`。实际报价、卖价、不破价判定交对应平台 `shop-ops` / `campaign-ops` 原 Skill及其现行门禁，附本次成本与证据，不自建第二套放行标准；库存积压也不能成为破价授权。
