# 库存、补货与资金占用

按SKU、仓库、同一单位和明确时点逐项计算。可使用本地算术核对，不新增脚本或依赖。保留精确中间数，量按约束取整，金额按结算精度处理；展示舍入不能改变边界判定。

## 1. 现货与需求

输入至少标明：评估时点`t0`、实物在库`P`、已预占`R`、不可售`U`、日需求`d`、供货周期`L`、安全期`S`、到货可售时点及需求单位。`R`与`U`须口径互斥，若重叠先去重；不可售包括待检/破损/冻结等已知不可供本次需求的数量。

`可用现货 A = P - R - U`，只有三个输入均已知、同范围同单位时给确定值。负值保留并标“库存账实/预占异常”，不能截成0掩盖；在核销重叠或盘点前不称库存规划安全完整。某输入未知则A未知，可分别报告已知数量与条件分支。

A是本次已声明规划口径，不直接等于直播可售量。若题面另给按数量锁定的安全库存，单列其归属及扣除点，按约定只扣一次，不与R/U或S天缓冲重复保留；关系未明则相应结论待核。转直播时按既有`on_hand-reserved-safety_stock`及原门禁重新核验，不把这里的A直接改名为直播可售或放行证明。

`d`保留观察窗口、订单/出库/签收等分母、取消与退货处理。备货依据实际消耗库存的需求，不因COD签收率低就按签收量替代出库需求。A已扣预占时，未来需求不再重复包含同一笔已预占订单；若给定需求含它，先作对账调整。拟回仓的退货未经到仓质检和重新释放，不列可售供给。

- `d>0`且A正常时，当前现货覆盖天数为`A/d`，不加未到货在途。与明确L比较时写“仅现货能/不能覆盖至新补货可售”，不能替代完整时间线。
- `d=0`是合法给定情景：目标覆盖需求为0、需求驱动补货缺口为0；覆盖天数写“不适用（日需求0）”，不除零或输出伪精确无穷天。库存仍占资金，保质/季节风险另查；不能按默认90天线自动称滞销或要求清仓。若库存本身负值，异常仍保留。
- `d`未知与0不同。L/S未知不默认7或15天。允许输出已知A、参数化公式、待确认情景；不捏造真实预测。观察均值外推为常量时明确“常量需求情景，不是预测”，有趋势/促销时按给定逐日曲线算，不套常量式。

## 2. 在途与到货前缺货

逐批记录批次ID、SKU/仓库/单位、归属、确认状态、数量、预分配/不可售份额、预计到仓日、质检/上架后的预计可售日、来源有效期。防止已收货批次同时出现在P和在途；在途预分配不与现货R重复扣。只有已确认、归属本计划、未被其他需求占用且可售时点在对应时窗内的净数量，才可用于该时窗抵扣。

取消/未确认订单、ETA未知、已过期承诺、目标仓不符或单位未换算的在途，不作确定供给。保留“未知/待核”状态，可另列条件情景；不把不计贡献写成已确认0。ETA晚于规划截止日的只列后续供给；ETA虽在截止日前但晚于需求时点的不能消除此前缺货。

按明确时间边界（如从`t0`起逐日先需求后到货，或有依据的具体时刻）建立事件表：

`累计净供给位置(t) = A + 截至t已可售的合格在途 - 截至t新增未预占需求`。

同时列每次到货前/后位置、首次不足时点和缺口；累计位置不能用`max(0,...)`掩盖短缺。若缺货订单取消或延迟交付，分别按所声明的缺货处理情景计算，不能默认后到货“补回已损失销售”。新拟补货也只能从其预计可售时点加入。到货当日顺序不明时列明边界并给保守分支，不能默认为到货先于需求。

## 3. 目标量、缺口与MOQ

常量需求且L/S以同一天单位给定时：

- `H = L + S`，明确规划截止时点`t0+H`。
- `目标覆盖量 T = d × H`。这是该情景的覆盖基准，可标类ROP参考，不由它直接命令下单。
- `I_H = 在[t0, t0+H]内合格且可用的在途净量`。
- `原始补货缺口 G = max(0, T - A - I_H)`；A或I_H关键数据未知时只给条件缺口，不能称确定缺口。负A虽可显示算术结果，仍须先处理库存异常。

G仅作期末数量差额；即使G=0，时间线也可能在较早时缺货。新单预计`t0+L`可售之前的缺口，常规补货不能解决。报告分列“期末缺口/到货前缺口”，把加急、调仓或需求调整列待审备选，不自动执行。

先确认MOQ含义和订单合法集合。若任务明确M同时为最小订量与补货整批倍数：`Q_target = ceil(G/M) × M`（G>0、M>0）；G=0时Q_target=0，不因有MOQ强行下单。若MOQ只是最低订量`m`、包装/订单步长另为`k`，按真实规则向上取合法量；如只能订k的正整数倍，则`Q_target = k × ceil(max(G,m)/k)`。不把最低订量擅自解释成倍数。单位为箱时同时列件数依据。MOQ或步长未知时给G与待核约束，不自填1。

量取整后重建时间线和期末余量。多个SKU共享MOQ/拼箱/预算时，先确认约束范围，不对每SKU重复套用一笔共享预算或把不兼容SKU拼满MOQ；无批准的分配优先级时给并列方案与取舍。

## 4. 采购支出与资金完整性

按同单位到仓成本`c`核：`采购资金需求 C(Q) = Q×c + 未包含于c的按量采购支出 + 按触发条件发生的固定支出`。

逐行列费用名称、币种、单价/固定额、数量基数、税含否、是否已含于c、付款时点、来源/有效期、已知状态。到仓成本可含货价、包装、采购物流、关税及入仓等，但须有明确组成；包含的费用不再叠加。按箱、每批、阶梯价或最低运费按相应规则算，不能伪装为恒定件价。固定支出是否随下单触发须明确；Q=0不代表所有已承诺或独立固定支出自动为0。

- 字段缺失、范围不明、报价过期或冲突均是未知。`known_subtotal`为可核实费用之和；`complete_cost=未知`并列缺项。不能把已知小计写“总资金”“全成本”或称预算通过。
- 经明确确认且适用于该SKU/数量/日期的0费用可用0，保留依据。显式0单价不等于其他费用0。未知固定费即使单件成本已知也阻断完整资金总额与确定性预算内量。
- `Q=0`时数量公式可能仍可知，但缺成本本身不被清零；说明未发生的按量支出和仍未知/已承诺的固定支出。单件到仓成本未知时，可交付数量规划，不报真实采购资金或利润。
- 资金占用不是利润、现金到账、GMV或经营收益。付款/账期与销售回款未给时不计算资金峰值或回收日；有明确收付事件才列时间表。不同日期的支出总额也不自动等于峰值占款。

## 5. 币种与预算

不同币种分别列`known_subtotal`与缺项。FX缺失/未知/过期时不能混加或判单一币种预算满足；数量与本币分项仍可交付。只有明确汇率方向（如`1 CNY = x IDR`）、来源、报价时点、有效截止、实际结算适用性、买卖方向/手续费及结算精度后才做标明的换算。反向换算正确取倒数，不能混用方向；实际金额按已给结算/舍入规则，保留未舍入值。另作保守上下界情景时，成本/占款可向上、可用预算可向下，但须标为界限，不改写实际费用或自行分配尾差；缺规则影响完整总额时仍待核。换算是同一规划的成本对账，不因此合并不同站点需求、利润或ROI。

预算B须明确币种、有效期、覆盖费用、已占用/已承诺、预留款及可用于本计划的余额。未知余额不能当全额可花。先算Q_target的完整C，再核预算；未设预算可报告资金需求并写“预算限制未提供”，不阻断其他完整计算。

下式B专指扣除占用/承诺/预留后的本计划可用余额。若输入是总预算，先按不重叠口径扣除；若题面已给可用余额则不再重复扣。

若已知同币种线性单位增量成本v>0、下单触发固定费F，且M是合法整批步长：

`Q_budget = M × floor(max(0, B - F) / (v×M))`。

F>B或不足最小合法订单时预算内可订量为0，不能向上凑MOQ。最低量/步长分开时，在合法订单集合中求`C(Q)≤B`的最大量；阶梯价、分批固定费或运费门槛不套上述线性式。未知费用/汇率只可给“基于已知支出的条件上限”，不能称可负担确定量。若v=0且获明确支持，不除零、不推荐无限量；检查固定费并说明预算不限制该情景的有限目标量，其他供给/单位/授权约束仍在。

目标方案与缩量方案分列：`Q_target`、完整资金需求、预算缺额；`Q_plan≤min(Q_target,Q_budget)`且满足订单约束时，重算期末短缺/余量与到货前缺货。预算内缩量只能称满足相应数量，不能称满足原覆盖目标。d>0时可给数量缺口对应的需求天数；无逐日需求时不伪造服务达成概率。B=0合法；未知预算与B=0不同。

## 6. 交接检查

交付与输入口径一致的A、T、G、合格在途、Q_target、预算内量、最终情景量、时间线缺口、分币种known_subtotal、complete_cost状态及费用缺项。异常/未知只阻断受影响结论：可有“库存可算、资金待核”或“选品仅相对比较、合成库存情景算清”。所有结果为离线草案/待审交接，三项执行授权均为false。库存超量不授权清仓价，预算充足不证明盈利；实际价格继续走原商城/活动门禁。
