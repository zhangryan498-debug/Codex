# Eight review modules
1. Four failures: diagnose delayed subject, ambiguity, audience irrelevance and absent curiosity. Quote speech/text or observed frame evidence. A picture can carry an otherwise vague opening; do not score a missing channel as failed.
2. Viewer panel: simulate casual scroller, skeptic, beginner, expert, buyer and peer creator. Limit each persona to actual opening evidence. Explain likely concerns without claiming real viewers watched or inventing disagreement. Prioritize personas appropriate to the brief.
3. Council: rank concrete repairs by relevant audience clarity, available proof and edit cost. Evidence failure outranks seductive wording. Distinguish reorder, cut, caption edit and reshoot. Give fewer priorities if fewer real problems exist.
4. Hook formats: consider supportable future change, actual experiment, teaching, investigation, fair contrarian argument and a visual-reveal layer. Each needs a true contrast, available first shot and immediate payoff. Drop a format requiring an absent experiment/cause/result; don't manufacture an opposing belief.
5. Niche tuner: use audience phrases only if provided as quotations; otherwise label them proposed wording. Scale stakes to the real problem. Product and regulated claims need appropriate evidence and later policy verification, not asserted legal certification.
6. Visual match: compare first-shot subject, readable text and spoken line. Choose only supplied/observed footage for existing shot selection; label new footage as a reshoot. Check caption legibility and UI obstruction only with actual frames and target layout. Avoid treating English 3–7-word guidance as a rigid Chinese character rule.
7. Lock-in: map the opening promise to the next available proof or explanation. Flag detours with exact evidence. Suggest cut/move or next lines that add information, not unverified proof. Do not invent when the payoff occurs.
8. Viral scout: optional, only with actual examples and dated provenance. Compare patterns, not copied wording. A few samples are hypotheses, not laws. Missing live access means no current trend verdict. Keep offline tests offline and do not introduce API costs.
