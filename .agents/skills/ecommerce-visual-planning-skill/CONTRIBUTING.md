# 贡献指南

## 最需要的贡献：真实合规案例

`references/compliance-rules.md` 里标【验】的部分，目前大多是推测方向，没有实操验证。**这是本项目最薄弱、也最需要补的地方。**

如果你有被平台驳回的真实经历，请按这个格式提 PR 或 Issue：

```markdown
- 平台：淘宝
- 时间：2026-03
- 品类：普通食品（花茶）
- 原文表述：「每天一杯，喝出好气色」
- 驳回理由：涉及功效宣称
- 修改后通过的表述：「花香清甜，适合下午茶时段」
```

**请只提交你自己亲历或有截图佐证的案例。** 推测、听说、二手转述的规则会让这个 Skill 变得比没有更危险——用户会以为它是可靠的。

## 其他可以贡献的

| 类型 | 说明 |
|---|---|
| 新品类层 | 按 `compliance-rules.md` 现有格式，每条标注【法】【推】【验】 |
| 驱动力分配优化 | 如果某类产品用现有四型判断不准，说明是什么品类、卡在哪 |
| 示例 | 完整走一遍流程的真实案例（可脱敏） |
| 英文版同步 | `SKILL.en.md` 与 `SKILL.md` 的内容对齐 |

## 改动 SKILL.md 时

改完跑一遍：

```bash
python3 tools/verify_skill.py
```

它会检查几件容易改坏的事：

- frontmatter 里的 `description` 是否还声明了用途边界（缺了模型会越界使用）
- 四种驱动力是否在中英文版本里都齐全
- **两道确认门的暂停句是否还在**——这两句被删掉，整套防返工机制就失效了
- 合规规则库是否还带着来源等级标注

## 不接受的改动

- 删除或弱化两道确认门
- 把「不用于」清单里的限制去掉
- 添加任何可能被当成法律意见的表述
- 在合规规则里写没有来源标注的条目
- 提交大体积二进制文件（展示图请用外链或压缩后的缩略图）

## 提交前

- [ ] `python3 tools/verify_skill.py` 通过
- [ ] 中英文版本内容一致
- [ ] 新增合规规则都带【法】【推】【验】标注
- [ ] 没有编造的检测编号、专利号、销量数据
