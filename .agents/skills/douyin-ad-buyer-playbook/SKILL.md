本段限定下方原方法论在当前项目中的适用范围；保留原正文以便追溯，不把历史政策或阈值当作实时事实。

- 正常项目任务先运行本 Skill 的 `scripts/resolve_project.py`，从 Skill 所在位置向上找到同时含 `runtime-agents/`、`docs/`、`templates/`、`data-pipeline/` 的项目根目录。正文内 `docs/`、`templates/`、`research/`、`data-pipeline/` 等路径均相对于该根目录，不是当前工作目录或 Skill 目录。可给解析脚本传入正文路径取得绝对路径；找不到资源须报告，不能臆造。
- 正常项目任务开始前读取下方引用的岗位知识、模板与数据渠道说明；需要的项目资源保持在根目录，共享资源不复制成容易失真的独立知识版本。
- 原“零网络／零凭证／完全跑通”等叙述，只能用作冻结快照离线复验的历史上下文。离线复验保持零网络门禁；实际市场研究按用户已授予的在线范围执行，工具和凭证是否可用须现场验证。不得把静态 Skill 安装或离线成功写成真实业务能力全部验证。
- 下方平台税费、评分门槛、履约方式、准入及活动政策均可能过期。实际经营决策前按当前站点官方来源复核日期、适用类目和履约模式；未复核明确待确认。JD 频次、历史比例仅是研究样本。

### 现行投放流程与报告标准（2026-11-09）

本节及后续平台专节是电商投放的执行口径。下方原方法论、原岗位说明和旧模板用于历史追溯或补充通用分析；其中旧入口、固定观察期、归因、费用、履约及处罚数值不作现行规则。单 Skill 模拟只用本 Skill 与题给输入即可完整执行。正常项目任务可按需读取模板和数据渠道；实际操作前另核账户权限、站点、预算限额、在投互斥及现行产品控件。

1. **建计划前**：记录平台／站点、币种时区、账户／店铺／商品／素材／直播间 ID、目标和归因范围。确认自有或授权、审核、库存与履约、商品链接可打开及身份一致。把基础预算、机动预算和品广费用分开，标注累计限额、允许控件、触发阈值及观察期。依据账户历史、保本线和风险余量选初始目标；后台推荐若低于经营护栏，先缩试验或搁置。预算下限超额度、身份不符或授权失效时暂停对应路径。
2. **自然流与素材**：搜索词、搜索／商城入口曝光→商品点击→支付→结算单列，记录标题、主图、规格、价格券、库存、时段和广告变更。每轮只改一个变量，其余保持或说明干扰。独立入口用于诊断与复测，重叠订单按 ID 核对，不与投放总 GMV 相加或由前后差直接认定增量。素材比较用同商品、可比时间窗和漏斗，先验挂链／授权，CTR 高而点击支付率低时查商品页承诺、价格券、规格与履约。没有素材级消耗和结算就留空该素材 CPA 与利润。
3. **经营账与目标口径**：同窗口、同对象、同批订单记录平台成交额 G、广告消耗 S、退款后结算收入 R、非广告变动成本 C。毛投产 G/S，结算回报 R/S，投前贡献 P=R−C，投后贡献 P−S。G/P 和 R/P 分别是对应报表口径的保本线，P 必须为正；采用净成交或综合成本出价时另以对应窗口和成本重算。结算已扣的退款及费用不可二扣。区分支付、签收、平台净成交、结算与贡献。预估与成熟回传分列，缺失或分母为零则 ROI 留空，不用公开竞品估算代填。
4. **盯盘与回退**：固定采样窗，记录更新时刻、齐数状态、累计消耗节奏、曝光／进房、有效停留、商品点击、支付、库存及排品事件。采样窗、平台归因窗和结算成熟期分开；逐窗回放只用当时已到数据。未齐数或过期冻结常规调参，已确认的库存、权限、履约、超支等硬风险可立即停对应推广及追加。低量先查权限、素材、库存、承接和节奏。有效样本有正贡献、同口径实际 ROI 达标并确有预算卡量时，仅加一次预算，受已批上限约束。预算未打满且确认目标过紧时，仅小步下调目标，守住同口径盈利护栏。需收紧效率且仍可安全观察时可小步上调目标；完整样本已证亏损先止损。未证实原因时保持基准。写明复测指标、观察时点、旧值和回退条件；暂停后先修复原因并核可靠数据，按旧基准或更低风险额度小量重启，重新累积达标窗口再扩。
5. **品广单列**：品广按品牌广告理解，独立触达目标、预算和审批。看去重触达、频次、CPM 或有效观看成本，按实际品牌产品可用控件执行。效果消耗与品牌消耗单列后再核合并贡献；直播间总体成交不能当品牌增量。无合适对照时，品牌增量与 ROI 留空。
6. **报告交付**：结论先行并标模拟或真实。逐路写计划、商品及素材身份、投放入口、控件／出价、预算与保本线、最小观察和止损。附自然入口与素材漏斗、平台投产与成熟经营账、逐窗调控表（时间／证据／动作与前后值／复测／回退），最后列负责人、缺口、来源和验收边界。实盘需核权限、账户报表、调控日志、真实成本和订单结算；模拟仅验证决策。按日／周／月复盘时沿用相同口径。

- **商品卡与挂链视频**：商品全域推商品使用可用商品卡、主图和授权挂链视频体裁。按抖音号×商品核互斥；同品卡／视频按素材或入口诊断，不默认拆成同商品重复计划。主页挂车与广告推广卡片分别核验。抖店／罗盘独立经营搜索与商城入口，优化标题、主图、规格价格、评价和库存；全域投放按整体口径优化并汇总自然及付费，分开的入口观察用于货架经营。调支付目标用整体支付口径，调净成交目标用后台同口径。

- **千川乘方**：乘方继承全域基础投放，同直播账号、同账号×商品按产品规则互斥。能升级时先核原计划状态、历史继承和互斥影响，实盘不在一场内反复切换。基础投放综合营销 ROI 为同段净成交金额÷整体消耗。商品侧含达人佣金／团长服务费的能力按实际开放和字段核成本。直播星选按账户与任务实际开放核对是否计入整体消耗，不能套商品佣金口径或重复扣成本。只用乘方生效期间同范围的分子分母；全域、乘方、追投和全场数据按模式／计划／时段分账。发现综合成本与同段基础消耗不符，先核导出截点、归因回补及成本明细，两套未对齐的试算均不能报作已核投产。

### 二次审查修订：可复现决策契约（2026-11-11，优先于上述概括及历史正文）

本节适用于双平台的离线决策与报告；不授予实盘操作权限。所有阈值必须来自当前已批准策略及适用平台控件，示例不是默认实盘值。数值复核使用项目 `scripts/ad_decision_contract.py`；这只是只读校验器，不连接平台执行。

1. **口径与时间可追溯**：每条 ROI、保本线附 metric（支付/净成交/结算/贡献）、scope（账户/商品/计划/订单群）、mode（窗口增量/累计）、区间、数据截止时刻、maturity、source/version。只能同口径比较。已齐窗增量为 ΔG/ΔS，不得拿累计数冒充；从累计求差要同一快照系列、非重置、同归因且标回补影响，不能据此直接声称广告因果边际回报。断档累计不插值。原模拟 20:05 的增量 275/50=5.50，已知累计345/85=4.0588，但含20:00未齐窗，累计同样暂读。不能把两数当同一指标。
2. **暂估与成熟阈值**：原直播盘中25%是假设贡献率，暂估保本4.00；收盘同批P=360、G=1650，成熟保本4.5833。二者可以并存，须分列适用时间与状态。盘中不得倒用后来结算；暂估过线只支持当前方向性观察，不证明成熟盈利。缺有效成熟/保守预测依据时不常规扩量。正式复盘以成熟账为准，解释偏差，不能把预估记录回填成成熟判断。
3. **扩量与卡量**：平均成熟ROI达标只是必要非充分条件。已验证预算限制证据需平台/账户/计划/控件、时刻、状态/原始回执；预算利用95%、泛化布尔或曝光损失都不能单独证明受预算限制，指标还需确实在该平台可得。离线题明确声明确认卡量可按题设接受，但标记模拟，不伪造截图。常规扩量需追加批次的可比成熟证据或保守边际预测与范围/假设，证明新增贡献可覆盖追加消耗；窗口同比增量不等于因果边际。缺边际依据时维持，或仅提出另有明确试验授权、单次额度/损失/比例上限、冷却窗与止损可执行条件的探索试验，不把探索写成已证盈利。原A仅有平均5.2及一次额度12，缺其余配置时不再直接180→192。
4. **库存与换品**：停线与复启线分开，复启线必须高于停线，含获批补货周期、安全缓冲及可售口径；未知复启阈值保持暂停，不自造42/50等值。复启要实际库存达到复启线、供货可确认、商品/价格券/权限/履约重新核验、数据齐新鲜，重新累积有效窗。商品身份或价格券变化独立于库存触发暂停受影响推广及追加，直到新绑定事实核验，不能以库存足够豁免；已经完整审核并预先批准的排品切换需按对应独立策略重新建基准，不混用旧窗。
5. **风险预算闭合**：各路径/币种/审批周期分账，可用余额=已批上限−已耗−未入账承诺，未知承诺不能当0。默认不借调；只有明确批准的来源路径、目标路径、金额与时间范围才能转移，双边同步扣增且不得重复占用。单次新增不得超过绝对上限、周期可用余额、已批比例×本次试验前可用余额、损失推导上限中的最小值；比例未批准则不自动追加。
6. **Max Delivery**：不能把Target ROI当成Max Delivery必有的硬ROI下限。若同口径保本B>0、可靠保守的追加回报下界r、贡献结构固定且无遗漏成本，损失系数=1−r/B。当0≤r<B，可推S≤剩余损失额度/(1−r/B)；r≥B时该公式不产生有限上限，但仍受审批/余额/现金流上限，不意味着无风险。无可信下界按零回收r=0；无成本上界或可存在额外损失时不能断言最大亏损等于花费。必须先扣已损失及监测延迟/停投生效期间的最坏风险预留，停止回执可验证；监控提醒不是硬预算锁。若账户最低可执行预算高于安全额度且无验证过的有效分段硬限，禁止开启。原独立活动批复230000、损失50000、最低160000，在缺r与延迟风险证明下不能排期，原结论撤回。
7. **自然搜索规模与效率**：分别报曝光与曝光→支付率。原例1500→2400、12→18，效率0.80%→0.75%（-0.05个百分点，-6.25%相对）；以旧效率分解，曝光规模项+7.2单、效率项-1.2单，合计+6。只是恒等式分解，非因果归因，不能证明曝光全部由标题带来。非随机前后对照保留干扰与待复测，不宣称标题净增量。
8. **不齐数据与承接指标**：统一四态：complete（同批齐新鲜）、partial（有值但未齐）、missing/stale（缺失或过期）、zero（真实零）。partial可列暂读数和假设估算但decision_eligible=false；missing不填数；0/0=null。不齐窗不计有效窗，不据其常规调参。硬停止优先。停留率/点击率必须说明分母、样本量、可比基线和已批阈值；66%→30%应标承接异常并查换品/流量结构，禁止无依据扩量，但30%本身不是所有类目的自动停线。需停/降档由已批门限及风险证据决定。
9. **控件、分级与冷却**：分别定义维持、降风险预算、收紧效率目标、暂停、受限试验和扩量；不能将“降目标”当通用降风险手段，降低ROI目标可能放松效率。动作前必须有同平台可用控件、已批单次步长、单日次数、冷却时长/完整窗、最小样本、盈利护栏及回退旧值。缺配置只提方案，不猜5.4或5.3后执行；硬风险可提前停止，不受冷却限制。每次仅改一项，记录前后值、时刻、触发证据、复测时刻、回退条件和实际回执。目标和护栏同值不必然错误：原A/B是独立题；同一配置也可同值，需明确目标是优化设定、护栏是风险门，两者触发动作不同。

报告逐项输出：原数据/来源、阈值版本与审批范围、动作、可执行性、缺口、模拟或真实；规则文档更新不等于模型全部通过或实际投放有效。不得破坏零分母留空、断档不插值、两套未对齐乘方试算均待核、收盘不倒推盘中、硬风险优先、平台最低预算不超批复等原纪律。

### 广告当前提案的主状态（2026-11-16）

对本岗当前提案（包括追加／探索试验），主 `research_state` 按本次动作适用的关键 `gate` 取最严格限制：已知硬失败为 `BLOCKED`；无硬失败但关键证据未齐为 `PENDING`；仅在本次限定研究条件均满足时为 `RESEARCH_ONLY`。当前 `decision`、计划中的拟执行动作及下游交接状态须一致，不能一面将当前成本或损失门禁列为待核，一面以“只是模拟／待批／开前再确认”为由写成现已可进入试验或扩量。历史逐窗动作按当时证据另列。

`facts`／`analysis` 可保留有出处的已知原观察及同原范围内的复盘算术；历史、外站或后来才到达的数据不能支持当前提案时，标 `decision_eligible=false`，保留原站点、币种、对象、时窗和限制，不强删有效原数。跨币种、量纲、对象或窗口不相容的目标计算仍留空，明确零与缺失不混。无关观察不可用，不应单独否定另有完整适用证据的安全研究方案。

附条件设计可另列补证、负责人和复核条件，但前置条件写进方案不等于已经满足。预算／花费帽、旧批次成熟利润、`complete` 或“成本完整”声明，均不能补齐新增批次的全成本与最大总损失证据，也不证明真实成本或权限可信；沿用上述风险预算、底价、库存及权限门禁，关键未知未解则当前提案保持待核。证据补齐后另版复评；条件完整的限定离线研究可接收，真实执行授权与工具范围仍按本任务已有授权分别核定，不由研究状态授予。

### 竞品交接的当前提案状态

仅在处理带当前比较／使用提案及结构化状态的竞品交接时，读取 `docs/竞品交接提案状态与事实用途规范.md`。主状态指当前提案；历史或分站事实可另列 `allowed_claims`／`allowed_use`，不得据此放宽当前提案的阻断或待核状态。接收主状态不得比上游主提案和本路交接更宽松；反证交回上游另版复核，保留本次状态。此约束不扩大为否定所有事实或改写无关经营逻辑；完整状态对应与边界仅见共用规范。

### 复盘口径、覆盖与增量验证（2026-11-16）

做广告或整体经营复盘时，读取 `docs/双平台广告复盘口径与增量验证规范.md` 并用 `templates/广告投手/复盘口径与增量验证表.md` 交付。至少输出 facts、measurement_basis、coverage_and_gaps、findings、next_actions、experiment_plan：缺失不作零，按同币种/同成熟窗口/同分母聚合比率，分别列整体经营与广告归因；销售同步上涨或渠道替代只作观察线索，需可靠对照才能估广告增量。不能执行实验时列可行方案、缺口和待授权事项，不伪造回执。

本节补充通用测量方法，不改变上述可复现决策契约、当前竞品提案状态或价格/库存/预算/权限门禁；不因复盘指标良好而破底价、把字段标记当可信成本或放行未知权限。TikTok 特有归因与控件不得套抖音。仅学习方法，不新增 Coupler 连接、外传、记忆写回或报告插件依赖。

# 抖音广告投手方法论

本 Skill 面向抖音（巨量千川）投放场景。**所有规则基于抖音国内生态，不可直接套用到 TikTok Ads**（账户结构、优化目标、净 ROI 口径完全不同）。

---

## 1. 岗位定义与考核指标

- **数据通道权威源**是项目 `docs/knowledge/data-channel.md`；取数走项目 `data-pipeline/` 下的采集器。**抖音侧零凭据通道已完全跑通**：热榜（`douyin_public.py`）+ 推荐流/话题真实体量/创作者画像/作品详情/评论（`douyin_feed.py`，推荐流自举，不需要种子 ID、不需要登录、不需要分享链接）。TikTok 侧采集器代码就绪，需 API token。外部数据只用于趋势与竞品判断，**经营口径（结算/真实退货/实收）必须来自店铺后台**。
- **取数三条纪律**：① L0 热榜的 `video_count` / `discuss_video_count` **不是话题体量**，不可当量级证据，只能用于词条间相对热度排序；② 话题真实体量看 `challenge/detail` 的 `view_count` / `user_count`；③ 抖音搜索端点需登录，**「热榜词 → 话题 cid」目前无免登录通道**，垂类批量采样需托管 API 或用户给一条分享链接作种子。

### 岗位定位
抖音电商效果广告账户的操盘手。真实 JD 的定义最准确：**"在 ROI 达标的前提下，尽可能放大消耗金额"**。

这个顺序不能颠倒。**先看 ROI 底线，再谈跑量。** 只冲消耗不管 ROI 是本岗位最典型的失败模式。

### 考核指标

| 指标 | 说明 | 注意 |
|---|---|---|
| **ROI（最高频核心指标）** | 多篇 JD 写明"对最终 ROI 负责" | **必须用净 ROI（扣仅退款）** |
| **消耗金额 / 跑量规模** | ROI 达标前提下放大 | 日消耗 10w+ 账号经验是常见门槛 |
| **GMV / 成交额** | 与消耗、ROI 并列为三大目标 | 标注支付口径还是结算口径 |
| 转化率 / 曝光量 | 中间指标 | 用于诊断，不作为最终指标 |
| 素材产出量 | 素材创意制作与测试的交付量 | MCN 口径下权重更高 |
| 数据报表交付 | 日/周/月度分析汇报 | 硬性要求，非可选项 |
| 三板块配比 | 商品卡/短视频/直播投放比例 | 真实 JD 明确要求 |

### 硬性任职门槛（真实 JD 统计）
- **学历**：大专及以上为主（岗位统计大专占约 46%），少数要求本科
- **经验**：1–3 年为主（占约 69%）；明确表述如"一年以上千川付费项目经验""最少半年以上巨量千川账户投放实战经验"
- **规模门槛分档**：无硬性消耗门槛（新手可投）/ 日消耗 10w+ 优先 / 累计消耗 >1000 万优先
- **工具**：千川后台（出价模式、扣费模式、素材审核与赔付机制、流量分配规则、权重分发机制）、Excel（透视表/PowerQuery/函数）、SQL、部分岗位要 Python、多平台后台能力（千川 + 金牛 + 鲁班 + DOU+/抖加 + 豆荚 + 本地推）
- **类目经验**：日用百货/家居/美妆/家电/食品等，打法差异大，跨类目直接上手容易跑不动

## 2. 标准作业流程（SOP）

### 2.1 接需求（第一步，不许跳过）

```
1. 销售额目标        ← 没有目标就无法设计投放
2. 类目与客单价      ← 决定素材方向与出价区间
3. 日预算            ← 决定账户结构与计划数量
4. ROI 底线          ← 最关键。ROI 底线决定能不能放量
5. 三板块配比预期    ← 商品卡/短视频/直播各占多少
6. 库存与履约能力    ← 断货时投放越猛损失越大
```

**五项未对齐就不要开始搭账户。**

### 2.2 测品跑品

```
选品工具（巨量云图 / 千川选品 / DOU+）测品
  ↓
跑出可投商品 + 素材方向
  ↓
小预算起量测试（观察素材 CTR 与转化）
  ↓
测出爆量素材与人群包
  ↓
进入正式投放
```

真实 JD 明确要求"选品测品、跑品"经验，这一步跳过是账户跑不动的常见根因。

### 2.3 账户搭建

```
新建广告计划
  ↓
设置投放场景（直播 / 短视频 / 商品卡 / 全域）
  ↓
设定出价方式、投放时段、人群定向
  ↓
上传素材创意
  ↓
预算与 ROI 目标设定
  ↓
【用 templates/广告投手/账户搭建清单.md 逐项自检】
  ↓
上线后 72 小时观察
```

### 2.4 日常盯盘

**盯四类状态**：

| 状态 | 看什么 | 异常处置 |
|---|---|---|
| 消耗速率 | 是否符合预算节奏 | 过快→降预算；不动→查素材量与审核状态 |
| 素材审核 | 是否有拒审、限流 | 拒审→查素材话术与资质；限流→查是否批量同质 |
| 账户赔付与限流 | 赔付机制触发、账户异常 | 按平台规则处理 |
| 库存 | 是否够放量 | 不足→降速，避免断货影响权重 |

### 2.5 素材迭代

```
与内容侧协商素材方向（不是投手单方面决定）
  ↓
拆解竞品素材 + 拆解自己跑出的素材
  ↓
单变量 A/B 测试
  ↓
把测试结论回灌给内容侧
```

真实 JD 明确："与内容组一起协商把控广告素材方向""对素材内容进行分析和拆解，根据分析数据反馈优化短视频"。**投手不参与素材方向协商，素材会很快衰减。**

### 2.6 复盘与汇报

日 / 周 / 月三级。真实 JD 明确要求"按日、周、月形成数据分析以及汇报"。每次复盘必须回答三件事：消耗多少、GMV 多少、ROI 多少、下一步做什么。

### 2.7 竞品投放监控

同类竞品的投放效果与投放素材是本岗位内嵌的竞对情报职责。真实 JD 写明"密切关注同类竞品投放效果和投放素材，关注市场投放行情""关注行业热点，定期收集竞品信息并进行分析和总结"。

## 3. 归因分层决策树

诊断投放问题时，按这个顺序走。**每层必须有指标证据才能下结论。**

```
投放异常（消耗不动 / ROI 不达标 / 成本超预期）
│
├─ L1 素材层（最高频根因）
│   ├─ CTR 低于类目均值 → 钩子/封面/前3秒问题
│   ├─ CTR 正常但 CVR 低 → 素材与商品脱节，或落地页问题
│   ├─ 素材审核未通过 → 话术违规/资质缺失
│   └─ 素材同质化衰减 → 素材数量不足或方向单一
│
├─ L2 人群层
│   ├─ 定向过窄 → 跑量受限
│   ├─ 人群包与商品不匹配
│   └─ 未用千川洞察的用户画像
│
├─ L3 出价层
│   ├─ 出价过高 → 成本超预期
│   ├─ 出价过低 → 跑不出量
│   └─ 出价模式与优化目标不匹配
│
├─ L4 商品页层
│   ├─ 商品信息质量分 <85 → 负向流量影响
│   ├─ 主图/详情页未承接素材承诺 → 点了不买
│   └─ 价格与素材展示不符
│
├─ L5 商品与价格层
│   ├─ 售价缺乏竞争力
│   ├─ 商品评分 <4.3 或近 30 天售出 <50 件 → 达人不可见，影响整体流量结构
│   └─ 库存不足
│
└─ L6 履约层
    ├─ 发货时效影响转化
    ├─ 退款率/仅退款吞噬实收 → 表面 ROI 达标但净 ROI 为负
    └─ 售后问题引发差评 → 影响商品权重
```

**归因纪律**：不能出现"可能是素材问题"这种没有数据的表述。要么给出指标证据，要么标注"需 XX 岗位补数据后确认"。

---

## 4. 净 ROI 计算规则（本岗位最重要的单条规则）

抖音有"仅退款"机制。**商家实收 = 支付 GMV − 退款金额**。所以：

```
表面 ROI = 成交金额 / 消耗
净 ROI  = (成交金额 − 退款金额) / 消耗
```

**在抖音投放的所有产出中，净 ROI 必须与表面 ROI 并列呈现。** 只有表面 ROI 的诊断表不予采纳。

**同时要校验投流费占营收比**：

```
投流费占营收比 = 消耗 / 营收

对照上限：多数类目 15%，美妆 30%
超出部分在企业所得税下可抵扣额度减少 → 实际成本上升
```

**当投流费占比触及上限时，即使 ROI 达标也不应继续加预算**——加得越多，实际利润越薄。这条经常被忽略。

## 5. 素材测试规范

### 5.1 单变量原则
**一次只测一个变量。** 多变量同测会导致归因失效，最后不知道是哪一环起作用。

可测变量：钩子 / 卖点 / 达人 / 节奏与时长 / 封面 / BGM / 话术 / 人群 / 落地页。

### 5.2 测试记录必备

【用 `templates/广告投手/素材AB测试记录表.md` 记录每次测试】
- 其他条件必须写明保持不变：出价、目标人群、预算、投放时段、商品、落地页
- 最小消耗门槛、观察期、判定日必须预先定义
- 净 ROI 列必填
- 迭代记录：从哪组出发、改了什么、结果如何

### 5.3 素材迭代方向
优先从**已跑出的爆量素材**出发做变体，而不是每次重新开一条新路。真实 JD 提到的有效手法包括：微付费翘自然流、三频共振（视频/直播/图文频次配合）、千川洞察反推人群与卖点。

## 6. 平台差异提示（抖音专属，不可外传）

以下均为抖音国内生态特有，**在 TikTok 侧不存在，反之亦然**：

| 抖音特有 | 说明 |
|---|---|
| **全域推广** | 以商品整体支付 ROI 为目标，不区分自然/付费流量 |
| **投流税** | 投流费占营收比上限（多数类目 15%、美妆 30%） |
| **商品信息质量分** | <85 有负向流量影响，目标 90+ |
| **仅退款** | 抖音特有的售后机制，直接吃掉实收 |
| **千川·乘方** | 千策/千意/千寻三大模块，预算与 ROI 一体化调度 |
| **电商内容加载率** | 刷 100 视频约见 9–12 条电商内容，超载伤体验 |
| **搜索定坑** | 短视频搜索词配置 3 个 + 搜索结果页前 5 商品位定坑 |
| **商品卡免佣** | 全年报名 1 次、每月完成 2–3 个任务，单月最高省百万元 |

## 7. 常见错误与雷区

| 错误 | 后果 | 正确做法 |
|---|---|---|
| **只冲消耗不管 ROI** | 消耗涨了利润塌了 | ROI 底线先行，达标才放量 |
| **用"自然流量没起量"解释失败** | 归因错位，浪费时间 | 全域推广下无此概念，查素材与账户结构 |
| **只看表面 ROI** | 假性盈利，仅退款吃掉利润 | 净 ROI 与表面 ROI 并列 |
| **忽略投流税上限** | 利润测算虚高 | 校验投流费占营收比 |
| **不懂平台机制** | 投不动、跑不出量、莫名限流 | 吃透出价/扣费/审核/赔付/流量分配/权重分发 |
| **只做直播投流** | 多板块配比时无法胜任 | 商品卡/短视频/直播三板块都要会 |
| **不参与素材方向协商** | 素材快速衰减 | 与内容组共商方向 |
| **多变量同测** | 归因失效 | 一次一个变量 |
| **不监控竞品投放** | 同赛道落后 | 盯竞品投放效果与素材 |
| **类目经验错配** | 跨类目直接上手跑不动 | 按类目积累经验 |
| **只盯消耗不盯转化链路** | 无法定位问题 | 日/周/月复盘，指标拆解 |
| **只做千川单平台** | 竞争力不足 | 多平台后台能力 |

---

## 8. 数据与规则的时效性规范

- **投流税比例、赔付机制、审核规则、流量分配规则**：均为平台政策，变动频繁。输出时必须标注来源与时点，并注明"需向平台侧复核"。
- **平台知识库的权威源**是项目 `docs/knowledge/platform-model.md`。与最新公告冲突时以公告为准，并**立即更新知识库**。
- **JD 中的门槛值（学历占比、经验年限分布等）**属岗位市场统计口径，标注来源平台与统计时点。
- **不确定的判断**标注置信度，并说明需要谁去验证。
