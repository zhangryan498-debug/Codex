# 抖音短视频编导方法论

本 Skill 面向抖系电商短视频编导场景。**TikTok 侧的本地化要求、限流红线、hashtag 逻辑完全不同，不可套用本手册。**

---

## 1. 岗位定义与考核指标

### 岗位定位
抖系电商链路的**动态素材操盘手**。JD 中最准确的一句定义：**"懂投流逻辑，不是纯宣传片编导"**。

与"创作者"的根本差别：
- 创作者追求"作品好看"
- **抖系编导追求"素材能跑量、能归因、能复用"**

产出物是**可批量投放、可归因、可复用的转化素材**：30–80 秒引流视频、15s/30s/60s 多版本投放素材、直播引流切片、千川投流素材。

### 考核指标

| 指标 | 说明 | JD 出处 |
|---|---|---|
| **点击率 / 转化率** | 素材漏斗前段指标 | 「过往工作经验有呈现良好的数据：点击率、转化率、CPM、千川消耗等」（河南屹坤） |
| **3 秒完播率 / 整体完播率** | 钩子有效性的直接度量 | 「跟踪千川素材投放数据（CTR、CVR、3 秒完播率、整体完播率）」（河南屹坤） |
| **千川消耗** | 素材的跑量能力 | 「面试可提供月消耗、ROI、转化成本等量化数据」 |
| **ROI / 转化成本** | 最终成交效率 | 「有高中类目爆款素材案例，懂短视频黄金 3 秒，数据敏感，结果导向」 |
| **素材审核通过率** | 合规硬指标 | 「严控素材审核风险，降低卡审、拒审率」 |
| **内容产能** | 日更条数、批量交付能力 | 「输出标准的脚本模板、分镜表格和拍剪 SOP」 |
| **素材复用率** | 资产化能力 | 「搭建并维护千川素材库，对脚本、拍摄素材、成片进行分类管理，提高素材复用率」 |

### 硬性任职门槛（98 篇智联真实 JD 统计）
- **学历**：大专 57% / 本科 34%。**千川/信息流方向基本要求本科**
- **年限**：1–3 年占 63%；「要求有经验，到岗即产出」——**抖系编导普遍拒绝培养期**
- **工具硬门槛**：**剪映专业版（必须）+ PR（Premiere Pro）**；AE（基础特效）、达芬奇（调色）为加分项；手机/微单/单反 + 稳定器 + 灯光 + 收音设备是拍摄硬门槛
- **作品集是硬门槛且比美工岗更严格**：58/98 篇要求作品集；「简历必须附带作品集；过往剪辑优质千川短视频素材和脚本文本，**无作品不安排面试**」——**明确一票否决**；优秀应届生如作品集过硬亦可考虑（作品集可替代学历）
- **经验成果要求是核心差异点**：编导岗的经验门槛不是"做过多少条"，而是**"跑通过什么数据"**

## 2. 选题策划方法

### 2.1 选题来源（七类，缺一不可追溯）

| 来源 | 说明 | 关联岗位 |
|---|---|---|
| 爆款拆解 | 来自拆解分析专员的拆解报告 | 拆解分析专员 |
| 平台热点 | 抖音热榜/热点榜 | — |
| 评论区与客服反馈 | 用户真实提问 | 客服/商城运营 |
| 选品上新 | 新品上市 | 选品运营 |
| 竞品动向 | 竞品在拍什么 | 竞品分析 |
| 达人共创 | 达人给出的命题 | 短视频编导 |
| 自有创意 | — | — |

**无来源标注的选题不得排期。** 无法判断是否值得投入。

### 2.2 选题优先级打分

| 维度 | 1–5 分 |
|---|---|
| 商品确定性（库存/价格/合规是否就绪） | |
| 需求确定性（是否有明确用户痛点） | |
| 钩子强度（3 秒能否抓住） | |
| 内容成本（拍摄难度/道具/场地） | |
| 竞争密度（同类内容是否已饱和） | |
| 平台匹配度（站内热点程度） | |

**排期规则**：商品确定性 <3 分的不排期（合规或库存没解决，拍了也不能上）。

### 2.3 选题到脚本的转化
选题库（`templates/短视频编导/选题库表.md`）→ 脚本模板（`templates/短视频编导/短视频脚本模板.md`）→ 拍摄清单（`templates/短视频编导/素材拍摄清单.md`）。

## 3. 脚本结构标准

### 3.1 前 3 秒（独立设计对象，必须单列评审）

| 项 | 要求 |
|---|---|
| 钩子类型 | 痛点场景 / 效果冲击 / 冲突反差 / 悬念 / 权威背书 / 原生对话 / 争议观点 / 稀缺 |
| 任务 | **降低划走率**，不是介绍产品 |
| 变体数量 | **同一商品至少 3 个钩子变体**，供投手 A/B |
| 评审 | 单独评审，不与主体脚本一起过 |

抖音侧常用：痛点场景、效果冲击。**原生对话/争议观点在 TikTok 侧更常见，抖音不可照搬。**

### 3.2 分镜表字段

镜号 | 时间 | 画面 | 口播/字幕 | 音效/BGM | 商品露出 | 拍摄要点

**时长建议**：抖音 15–45 秒；千川投放素材常需 15s/30s/60s 多版本。

### 3.3 转化设计（不可省）

| 项 | 说明 |
|---|---|
| 转化动作 | 挂车 / 引导搜索 / 引导进直播间 / 关注 |
| CTA 话术与出现时机 | |
| **埋点** | **抖音：同步配置短视频搜索词 3 个 + 搜索结果页定坑**（搜索转化率约为推荐 12 倍） |
| 评论区引导 | |

### 3.4 内容形态（JD 高频要求）

口播脚本、场景种草脚本、剧情脚本、带货脚本——**JD 明确要求能区分脚本类型**。

## 4. 拍摄执行流程

```
拍摄前
  ├─ 脚本定稿，前 3 秒已单独评审
  ├─ 分镜表交付到位
  ├─ 口播稿定稿 + 违禁词检查
  ├─ 样品核对（外观/规格/数量）
  ├─ 资质与认证文件备齐（美妆/食品/电器）
  ├─ 器材：设备电量存储、麦克风收音测试、灯光方案
  ├─ 场地：背景干净、无杂物与品牌露出
  ├─ 人员：出镜形象与账号人设一致、肖像授权
  ↓
拍摄中（你是现场主导者）
  ├─ 协调出镜、场地、道具
  ├─ 引导出镜人情绪与表现
  ├─ 把控节奏与画面质量
  ↓
现场质检（当场做，不留到后期）
  ├─ 前 3 秒有冲突/效果/痛点，不是平淡开场
  ├─ 画面干净、主体突出、构图舒服
  ├─ 收音清晰无环境噪音
  ├─ 商品细节拍清楚（材质/工艺/尺寸）
  ├─ 口播无错词、无禁用词
  ├─ 演示动作完整可读
  ├─ 字幕区域留白（后期加字不挡画面）
  └─ 无第三方品牌/版权露出
  ↓
收工清点
  ├─ 素材条数核对
  ├─ 分组情况
  └─ 备份（硬盘 + 云盘 + 本地）
```

**命名规范**：`[平台]-[日期]-[商品]-[脚本编号]-[镜号]-[版本]`
例：`DY-20261104-面膜-T003-01-v1`

## 5. 素材复盘与归因三分类

发布后必须回填数据，并**判定问题归类**——这一步决定谁去解决。

| 数据表现 | 归因 | 交给谁 |
|---|---|---|
| 低播放 + 低转化 | **钩子问题**，前置信息太慢 | 自己改前 3 秒 |
| 低播放 + 高转化 | 内容形式有效，**钩子需加强** | 自己改前 3 秒 + 换发布策略 |
| 高播放 + 低转化 | **问题不在内容**，在商品页或人群 | 转交货架商城运营 / 广告投手 |

**其他必须排除的干扰项**：发布时段、账号标签、流量池冷启动情况。**先排除这些，再下内容结论。**

**爆款判定口径**：与拆解分析专员统一（同一账号内对比中位数），口径一经确定不得中途更改。

## 6. 资产沉淀（JD 明确要求，MCN 口径核心指标）

| 资产 | 内容 | 价值 |
|---|---|---|
| **脚本模板** | 标准化的脚本骨架 | 提效 |
| **分镜表格** | 标准分镜字段 | 提效 |
| **拍剪 SOP** | 拍摄与剪辑流程 | 提效 + 质量一致 |
| **素材库** | 脚本/拍摄素材/成片分类管理 | **提高素材复用率** |
| **内容优化 SOP** | A/B 测试得出的结构规律 | **可复制的方法论** |

**AIGC 使用**：JD 已普遍要求善用 AI 做脚本创作、素材生成、创意发散、分镜设计、视觉参考。**抖音侧注意平台规则，不得 AI 换脸**；AI 生成内容按平台要求标注。

## 8. 常见错误与雷区

| 错误 | 后果 | 正确做法 |
|---|---|---|
| **做成"纯宣传片编导"** | 素材跑不动量，这是 JD 反复点名的失败模式 | 一切以钩子、CTR、CVR、ROI 为导向 |
| **只拍不管数据** | 素材快速衰减，无法归因 | 发布后必须回填并判定归因三分类 |
| **不写搜索词** | 丢掉转化率约为推荐 12 倍的搜索入口 | 脚本定稿同步产出 3 个搜索词 |
| **忽视合规自检** | 卡审、拒审，直接影响跑量 | 上线前自检，美妆大健康额外管控 |
| **把作品集当作品** | 无爆款数据支撑 | 作品集要体现 CTR/CVR/消耗/ROI |
| **前 3 秒平淡开场** | 划走率高，直接死 | 前 3 秒单独设计 + 单独评审 + 3 个变体 |
| **现场问题留到后期** | 补拍浪费档期 | 现场质检当场做 |
| **无来源选题直接排期** | 投入无法回收 | 选题必须可追溯 |
| **不沉淀资产** | 产能无法复制，MCN 口径拿不到分 | 模板、SOP、素材库持续维护 |
| **只投不管数** | 无法沉淀方法论 | A/B 测试单变量，形成优化 SOP |
| **高播放低转化还在改内容** | 改错方向，浪费时间 | 归因三分类，高播放低转化转交商品页/人群 |
| **混淆抖音与 TikTok 内容逻辑** | 本地化不足导致起不来 | 抖音的钩子套路不可直接搬 |

## 9. 数据与规则的时效性规范

- **平台审核规则、违禁词库、千川规则**：变动频繁。输出时标注来源与时点，并注明需复核。
- **爆款判定口径、完播率基准**：属经验区间，标注为参考值。
- **数据通道权威源**是项目 `docs/knowledge/data-channel.md`；取数走项目 `data-pipeline/` 下的采集器。**抖音侧零凭据通道已完全跑通**：热榜（`douyin_public.py`）+ 推荐流/话题真实体量/创作者画像/作品详情/评论（`douyin_feed.py`，推荐流自举，不需要种子 ID、不需要登录、不需要分享链接）。TikTok 侧采集器代码就绪，需 API token。外部数据只用于趋势与竞品判断，**经营口径（结算/真实退货/实收）必须来自店铺后台**。
- **取数三条纪律**：① L0 热榜的 `video_count` / `discuss_video_count` **不是话题体量**，不可当量级证据，只能用于词条间相对热度排序；② 话题真实体量看 `challenge/detail` 的 `view_count` / `user_count`；③ 抖音搜索端点需登录，**「热榜词 → 话题 cid」目前无免登录通道**，垂类批量采样需托管 API 或用户给一条分享链接作种子。
- **平台知识库权威源**是项目 `docs/knowledge/platform-model.md`；与最新公告冲突以公告为准并立即更新。
- **数据口径**：完播率、CTR、CVR 的统计口径需与投手对齐，避免同一指标两种算法。
