# 抖音前端美工设计师方法论

本 Skill 面向抖系电商前端视觉场景。**TikTok 侧需额外做四层本地化核验（语言/货币/场景/文化符号），不可套用本手册。**

---

## 1. 岗位定义与考核指标

### 岗位定位
抖系电商链路的**商品视觉前端产出者**，对**点击率与转化率**两个漏斗前段指标负责。

与"传统淘宝美工"的差别：
- 淘宝美工：主图服务于搜索货架，尺寸规整
- **抖系视觉：第一触点在推荐流**，用户停留极短 → 主图必须在极短时间内完成信息传达

JD 里对能力的定义很准：「具备数据驱动的设计思维，能够通过点击率、转化率等数据反馈复盘设计效果，**提炼可复用的设计方法论，而非仅凭主观审美开展工作**」。

### 考核指标（JD 明确写出的）

| 指标 | 篇数 | 说明 |
|---|---|---|
| **主图点击率** | 50/64 | **最核心的漏斗指标** |
| **详情页转化率** | 50/64 | 与点击率并列 |
| 视觉规范一致性 | 37/64 | 跨 SKU、跨页面统一度 |
| 交付时效 | 普遍 | 按时交付、快速响应改图 |
| 素材复用率 / 出图效率 | 37/64 | 模板库与素材库建设产出 |
| 直播即时改图响应速度 | 直播电商类样本 | **分钟级响应** |
| 大促视觉落地完成度 | 普遍 | 618/双11 节点 |

### 指标体系的关键转变
抖系商家美工的 KPI 已从"出图数量"转向**"点击率 × 转化率 × 可复用资产沉淀"**三件套：
1. **漏斗前段效率**——有数据反馈的岗位把它写成硬性任职要求
2. **规范一致性**——从"个人审美"转向"系统化规范"（字号≤3级、卖点≤2个等量化约束）
3. **资产化**——模板库、素材库、规范文档成为资深岗的明确产出物

### 硬性任职门槛（64 篇智联真实 JD 统计）
- **学历**：大专为主（56/64 篇要求大专及以上），本科仅约 11%（**显著低于编导岗的 34%**）
- **年限**：1–3 年为主（占约 56%），作品集要求**约 19%**（编导岗为 58%——美工岗作品集门槛明显更低）
- **软件硬门槛**：**Photoshop（必需）**、**Illustrator（AI）**；CDR（工业/印刷类）、C4D/3D MAX（建模渲染）、PR/AE（信息流动效）、剪映（封面动效）为加分
- **AI 工具**：AI 场景合成、背景替换、AI 商品图生成已是常规要求，用于降低实拍依赖
- **流程工具**：Excel（数据复盘表、素材台账）、素材分类归档（原图/精修图/源文件，按类目/SKU/场景/时效）

## 2. 主图设计规范

> 项目模板：`templates/美工设计/主图需求单.md`（需求单）、`templates/美工设计/详情页结构模板.md`（详情页结构）、`templates/美工设计/视觉验收清单.md`（交付验收）

### 2.1 五槽位结构

每张主图按五个槽位思考，**但单张只承载 ≤2 个核心卖点**：

| 槽位 | 内容 | 要求 |
|---|---|---|
| ① 商品特点 | 是什么 | 客观描述 |
| ② 优势 | 比别人好在哪 | **必须有对比对象** |
| ③ 利益点 | 用户的感官/心理收益 | 可含价格机制（如立减），须与实际一致 |
| ④ 证明 | 销量/评价/资质/检测 | 竞品主图最常缺这一槽 |
| ⑤ 场景 | 使用画面 | 让用户看到自己 |

**主图视频**：≥6 秒，20–30 秒为宜，竖屏优于横屏；标品可考虑测评类，非标可考虑场景/穿搭类。

### 2.2 量化约束（JD 明确）

| 约束 | 值 | 来源 |
|---|---|---|
| 单张主图核心卖点数 | **≤2 个**，且主次分明 | 斑马南昌供应链 |
| 字号层级 | **≤3 级** | 斑马南昌供应链 |
| 角标规格、色彩配比、安全边距 | 需规范化 | 视觉规范文档要求 |
| 缩略图可读性 | 核心信息在缩略图状态下可读 | 平台特性推论 |

### 2.3 与货架流量的联动
- **商品信息质量分 ≥85（目标 90+）**，<85 有负向流量影响 → 视觉产出直接关联流量
- **销量 >10 单、好评率 ≥85%（目标 90%）、详细评价 ≥10 条** 构成好商品门槛
- **规格/细节图直接降低退货率** → 是成本控制，不只是审美

## 3. 详情页结构方法

### 3.1 先疑虑，后模块

```
用户从看到主图到下单，会依次产生疑虑
  ↓
列出疑虑清单（8 项）
  ↓
每个疑虑必须对应一个解答模块
  ↓
再排模块顺序
  ↓
最后才做视觉
```

**8 项标准疑虑清单**：
1. 这是什么 / 适合我吗
2. 质量好不好 / 真假
3. 规格/尺码合不合适
4. 怎么用 / 效果如何
5. 值不值这个价
6. 售后怎么保障
7. 什么时候到 / 怎么退
8. 为什么这么多人买

### 3.2 十段模块骨架
首屏（承接主图）→ 痛点共鸣 → 核心卖点（只打 1 个，深讲）→ 演示/实测 → 细节特写 → 规格/尺码 → 信任背书 → 使用说明 → 售后保障 → 促销信息

### 3.3 与编导的配合
详情页要承接短视频的承诺。**短视频说的、详情页没兑现 → 点了不买或退货。** 卖点排序需与编导的主打卖点对齐。

## 4. AI 生图使用规范

JD 已普遍要求（AI 场景合成、背景替换、AI 商品图生成），但有硬约束：

| 约束 | 说明 |
|---|---|
| **不得 AI 换脸** | 平台红线，抖音侧明确 |
| **AI 生成内容需标注** | 按平台要求 |
| **不得盗用同行主图** | 版权风险 |
| **商品必须真实** | AI 生成的商品图与实物不一致 → 投诉仲裁，赔付可达订单金额 150% |
| **AI 图与实拍图的边界要交代** | 涉及材质、颜色、尺寸的必须用实拍 |

## 5. 视觉资产沉淀体系

这是资深岗的明确产出物，也是 MCN 口径的核心指标：

| 资产 | 内容 |
|---|---|
| **视觉规范文档** | 字号层级（≤3 级）、角标规格、色彩配比、安全边距 |
| **爆品视觉模板库** | 首屏钩子结构、卖点排布节奏、信任背书位置、促销色彩规范 |
| **类目通用模板库** | 各类目通用模板，提升出图效率 |
| **视觉素材库** | 原图/精修图/源文件分类归档，按类目、SKU、场景、时效 |
| **拍摄需求清单** | 构图留白、光线运用、模特气质匹配（给拍摄方用） |

**命名与归档规范**（JD 明确要求）：分类归档原图、精修图、源文件，同步更新商品视觉资产。

## 6. 交付与验收流程

```
需求单确认（目标、疑虑、信息层级已明确）
  ↓
主图设计（五槽位，≤2 卖点）
  ↓
详情页结构（疑虑清单 → 模块）
  ↓
视觉制作
  ↓
【自检：视觉验收清单】
  ↓
【他检：由设计以外的人复检】← 不可跳过
  ↓
交付（源文件 + 各尺寸导出 + 文案表 + 统一命名）
  ↓
上线
  ↓
数据回收（CTR / 转化率 / 停留 / 退货率）
  ↓
回写视觉规范
```

**自检+他检的双重机制**是本岗位质量的关键。自己检查自己的设计最容易漏掉习惯性错误。

## 7. 常见错误与雷区

| 错误 | 后果 | 正确做法 |
|---|---|---|
| **按出图数量交付** | KPI 错位，无法证明价值 | 交付后必须回收数据并回写规范 |
| **单图讲三件事** | 缩略图无重点，点击率低 | 单图 ≤2 个核心卖点 |
| **字号层级过多** | 缩略图状态糊 | ≤3 级 |
| **缺证明槽位** | 信任建立不起来 | 销量/评价/资质/检测要上 |
| **详情页只讲好处不讲疑虑** | 用户疑虑没解决 → 点了不买或退货 | 8 项疑虑逐项解答 |
| **尺码信息缺失或出错** | 直接放大退货率 | 尺码对照 + 尺寸标注，准确无误 |
| **详情与实物不符** | 投诉仲裁，赔付可达订单金额 150% | 商品必须真实，AI 图慎用于材质尺寸 |
| **虚假划线价** | 价格欺诈 | 价格机制与实际一致 |
| **只在直播前出图，不留改图余量** | 直播中改不动 | 分钟级改图响应能力 |
| **不沉淀模板与素材库** | 出图效率上不去，MCN 口径拿不到分 | 规范/模板/素材库持续维护 |
| **凭主观审美工作** | 与数据脱节 | 数据驱动迭代，提炼方法论 |
| **盗用同行主图 / AI 换脸** | 违规下架 | 授权齐全 |
| **源文件与切图不交付** | 运营无法自助改图 | 交付源文件 + 切图 + 文案表 |

## 9. 数据与规则的时效性规范

- **平台视觉规范、类目要求、违禁词**：变动频繁，标注来源与时点。
- **商品信息质量分口径**：以平台最新公告为准。
- **数据通道权威源**是项目 `docs/knowledge/data-channel.md`；取数走项目 `data-pipeline/` 下的采集器。**抖音侧零凭据通道已完全跑通**：热榜（`douyin_public.py`）+ 推荐流/话题真实体量/创作者画像/作品详情/评论（`douyin_feed.py`，推荐流自举，不需要种子 ID、不需要登录、不需要分享链接）。TikTok 侧采集器代码就绪，需 API token。外部数据只用于趋势与竞品判断，**经营口径（结算/真实退货/实收）必须来自店铺后台**。
- **取数三条纪律**：① L0 热榜的 `video_count` / `discuss_video_count` **不是话题体量**，不可当量级证据，只能用于词条间相对热度排序；② 话题真实体量看 `challenge/detail` 的 `view_count` / `user_count`；③ 抖音搜索端点需登录，**「热榜词 → 话题 cid」目前无免登录通道**，垂类批量采样需托管 API 或用户给一条分享链接作种子。
- **平台知识库权威源**是项目 `docs/knowledge/platform-model.md`；与最新公告冲突以公告为准并立即更新。
- **数据口径**：主图点击率、详情页转化率的统计口径需与投手、商城运营对齐，避免同一指标两种算法。
- **不确定判断标注置信度**，说明需要谁去验证。
