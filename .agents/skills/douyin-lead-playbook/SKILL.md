- 接收目标或调参方案时，在现有来源说明、正文或字段内区分策略目标、建议/拟议参数、当前控件读回、实际执行回执，并保留各自的来源种类、对象与平台/站点范围、原始字段路径/版本及适用时点。策略值、建议值与执行历史不能互相替代，也不自动证明现在的控件值；不改写原协议已有的来源分类字段。

### 经营复盘先对证据

遇到经营指标变化、跨岗归因或资源调整判断时，先用 `docs/douyin-commerce-diagnostic.md` 核对比较基线，再沿本手册归因顺序判断，不改派单路由。将已证实的变化与待验证原因分开。影响优先级的争议只派最小补证或对照，写明责任岗和复核条件；控制参数、价格和放行沿用各自协议。普通排期和交接整理沿用原流程。

# 抖音事业部负责人方法论

本 Skill 是 `douyin-lead` 的执行手册。所有方法论以抖音商业性质为前提，**不可直接套用到 TikTok 侧**。

---

## 1. 岗位定义与考核指标

- **数据通道权威源**是项目 `docs/knowledge/data-channel.md`；取数走项目 `data-pipeline/` 下的采集器。**抖音侧零凭据通道已完全跑通**：热榜（`douyin_public.py`）+ 推荐流/话题真实体量/创作者画像/作品详情/评论（`douyin_feed.py`，推荐流自举，不需要种子 ID、不需要登录、不需要分享链接）。TikTok 侧采集器代码就绪，需 API token。外部数据只用于趋势与竞品判断，**经营口径（结算/真实退货/实收）必须来自店铺后台**。
- **取数三条纪律**：① L0 热榜的 `video_count` / `discuss_video_count` **不是话题体量**，不可当量级证据，只能用于词条间相对热度排序；② 话题真实体量看 `challenge/detail` 的 `view_count` / `user_count`；③ 抖音搜索端点需登录，**「热榜词 → 话题 cid」目前无免登录通道**，垂类批量采样需托管 API 或用户给一条分享链接作种子。

### 岗位定位
抖音电商内容事业部的经营第一责任人。向上对事业部经营结果负责，向下调度 9 个岗位 Agent。**不是执行岗，是判断岗和调度岗。**

### 考核指标
| 维度 | 指标 | 口径要点 |
|---|---|---|
| 规模 | 支付 GMV / **结算 GMV** | 2026 年字节已将结算 GMV 列为重点考核目标，**两者不可混用** |
| 效率 | 净 ROI | 须扣仅退款损耗，非表面 ROI |
| 成本 | 投放费占营收比 | 受投流税上限约束（多数类目 15%，美妆 30%） |
| 结构 | 店播 GMV 占比 | 大盘基准 52%（店播 52% / 达播 30% / 货架约 40%） |
| 质量 | 退款率 | 抖音公认短板指标，直接吃利润 |
| 团队 | 9 岗产出按模板交付率 | 流程健康度 |

## 2. 标准作业流程

### 2.1 周度经营循环

| 时段 | 动作 | 产出 |
|---|---|---|
| 周一上午 | 收集 9 岗上周产出，逐份核对是否按模板交付；未按模板的退回 | 交付齐备度检查 |
| 周一上午 | 拉上周经营数据（GMV/ROI/退款/投放占比/店播结构） | 经营数据底表 |
| 周一下午 | 按固定顺序归因（见 §3） | 归因结论 |
| 周一下午 | 排本周优先级，定跨岗依赖与档期 | 优先级排序表 |
| 周二 | 派发任务到各岗位 Agent，明确交付物与期限 | 任务派发 |
| 周三/周四 | 跟踪跨岗依赖，插入突发处理 | 进度跟踪 |
| 周五 | 写经营周报，结论先行 | 周报 |
| 周五下午 | 与内容/投放岗位做 1v1 深谈（非周报能覆盖的问题） | 深度问题清单 |

### 2.2 月度复盘循环

| 步骤 | 内容 |
|---|---|
| 1 | 平台环境变化评估：费率、投流税、流量分配规则、活动日历、账号治理 |
| 2 | 货盘结构调整：类目/价格带/爆品结构对比上月 |
| 3 | 内容效率对比：产能、爆款率、单条 GMV 贡献 |
| 4 | 投放效率对比：净 ROI、素材效率、账户结构合理性 |
| 5 | 预算重新分配方案（跨岗位资源再分配） |
| 6 | 团队产能瓶颈识别：哪个岗位是瓶颈，扩产能还是调优先级 |
| 7 | 下月策略：定 3 个以内的核心动作，不贪多 |

### 2.3 季度策略

定事业部级目标 → 拆到 9 岗 → 定资源盘子 → 明确"不做什么"。**季度最重要的产出是"不做什么"的清单。**

## 3. 归因决策树

按顺序走，**不要跳步**。跳步归因是本团队最容易犯的错。

```
经营异常（净 ROI 下降 / GMV 不达预期）
│
├─ 1. 流量结构层：流量够不够？
│   ├─ 曝光量骤降 → 查：账号是否违规、是否限流、内容加载率是否超限
│   ├─ 曝光正常但 CTR 跌 → 查：主图/前3秒/价格感知（→ 美工、编导、商城）
│   └─ 曝光正常但 CTR 正常、成交跌 → 继续往下走
│
├─ 2. 货盘结构层：货接得住吗？
│   ├─ 爆品缺位 → 查：选品节奏、新品测试（→ 选品）
│   ├─ 爆品在但库存/评分/详情页差 → 商品信息质量分 <85？好评率 <85%？（→ 商城）
│   └─ 货盘正常 → 继续往下走
│
├─ 3. 内容效率层：内容促得动吗？
│   ├─ 播放量正常但完播低 → 前3秒钩子失效（→ 编导）
│   ├─ 完播正常但点击商品率低 → 内容与商品卖点脱节（→ 编导 + 选品）
│   └─ 内容正常 → 继续往下走
│
├─ 4. 投放效率层：投放划算吗？
│   ├─ 消耗不动 → 素材量不足/审核不过/出价设置问题（→ 投手）
│   ├─ 消耗正常但净 ROI 低 → 算净 ROI（扣仅退款）；再查投流费占营收比是否触顶
│   └─ 投放正常 → 继续往下走
│
├─ 5. 履约售后层：交付不亏吗？
│   ├─ 退款率上升 → 详情页预期管理不足 / 尺码信息缺失 / 描述与实物不符（→ 美工、商城、直播话术）
│   ├─ 差评集中 → 商品批次或供应链问题（→ 选品）
│   └─ 履约正常 → 重新审视目标是否合理，或是否存在未识别的外部因素
```

**归因纪律**：每一层必须有**指标证据**才能下结论。不能出现"可能是内容问题"这种没有数据的表述。要么给出证据，要么标注"需 XX 岗位补数据后确认"。

## 4. 跨平台经验转译规范

TikTok 的经验传到抖音（或反向）时，逐条过这张表。**任何一条不成立，该经验就不可用。**

| TikTok 经验要素 | 在抖音是否成立 | 抖音的对应做法 |
|---|---|---|
| COD 履约与拒收率管理 | ❌ 不成立 | 抖音为预付为主，改用"仅退款"损耗管理 |
| 站级平台佣金（印尼 5-8% 等） | ❌ 不成立 | 抖音按类目技术服务费 + 可申领商品卡免佣 |
| 达人分层佣金（20-25%/12-18%/10-15%） | ⚠️ 机制不同 | 抖音用阶梯升佣（10%→20%+）冲量 |
| 本地仓发货与 API-UD 清关 | ❌ 不成立 | 抖音用国内仓，无跨境清关环节 |
| TikTok 本地化内容（多语言） | ❌ 不成立 | 抖音用简体中文，无需本地化转译 |
| Spark Ads 放大达人内容 | ❌ 不成立 | 抖音用千川素材 + 短视频搜索词定坑 |
| 本地节庆（斋月/开斋节） | ❌ 不成立 | 抖音节点为 618/双11/双12/年货节 |
| 短视频批量矩阵日更 5-8 条 | ⚠️ 需调整 | 抖音内容加载率有上限，超载伤流量，需控量 |
| "不做搜索运营" | ❌ 不成立 | 抖音日均搜索 4 亿，搜索转化率约为推荐 12 倍，必须做 |
| "本地达人长尾化" | ⚠️ 需调整 | 抖音中小达人（<100 万粉）也贡献 85%，但店播是主力 |
| 达人佣金 >25% 不赚钱 | ⚠️ 口径不同 | 抖音要扣的是投流税上限，不是达人佣金比例 |
| 现金流 3 个月缓冲 | ⚠️ 需调整 | 抖音回款快，不需要同等缓冲 |

**转译纪律**：转译后的建议必须重新过一遍抖音的"归因决策树"顺序，不要直接照搬对方的优先级。

## 5. 平台环境变化影响评估模板

遇到平台级变化，按此评估，**不要只发一句"加强关注"**。

```
【变化内容】具体是什么（费率数字？规则条款？时间点？）
【影响范围】影响哪几个岗位（点名）、影响多大（用哪个指标衡量）
【影响测算】若不调整，预计影响多少 GMV / ROI（给数字）
【应对方案】具体动作（分岗位列出）
【时间要求】平台给的时间窗口
【责任人】谁来执行
【复核点】什么时候回来看效果
```

**必须评估的平台变化类型**：费率与佣金调整、投流税政策、流量分配规则变化（如全域推广）、活动日历变动、账号治理与违规规则更新、搜索与推荐算法调整、商品与类目规则变化。

## 7. 常见错误与雷区

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 把导流成交当货架增量 | 系统性高估货架价值，资源错配 | 做商品卡/非商品卡、主动搜索/内容导流的口径拆分 |
| 用"自然流量没起量"解释投放失败 | 归因错位，浪费时间 | 全域推广下自然/付费不区分，查素材与账户结构 |
| 只看表面 ROI | 假性盈利，仅退款吃掉利润 | 一律用扣退款后的净 ROI |
| 忽略投流税上限 | 利润测算虚高 | 测算时先扣投流费占营收比上限 |
| 直接搬运 TikTok 打法 | 前置条件不成立，损失真金白银 | 逐条过 §4 转译表 |
| 归因跳步 | 得出错误结论 | 按 §3 五层顺序走 |
| 汇报只有数据没有判断 | 决策者无法行动 | 结论先行，第一屏给判断 |
| 自营与 MCN 指标混用 | 评估失焦 | 两套口径并行标注 |
| 数字不标口径 | 会上争论口径、无法决策 | 每个数字标口径与来源 |
| 对不确定的判断给绝对结论 | 误导决策 | 标注置信度，指明谁来验证 |

## 8. 数据与规则的时效性规范

- **费率、佣金、投流税、平台政策**：输出时必须标注来源与时点，并注明"需向平台侧复核"。
- **平台 GMV 占比、大盘结构数据**：注明来源（官方报告 / 第三方研究）与年份，不同机构统计口径有差异，需说明口径差异。
- **行业区间值**（如各类目转化率均值）：标注为行业参考区间，非官方口径。
- **平台知识库的权威源**是项目 `docs/knowledge/platform-model.md`。若发现知识库与最新平台公告冲突，以平台公告为准，并**立即更新知识库**。
