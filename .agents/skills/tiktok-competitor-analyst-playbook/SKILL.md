### 已固化：竞店、竞品、选品命中与货源联动

执行前读取 `docs/双平台竞店与竞品对比规范.md`，按 `templates/竞品分析/双平台竞店竞品对比报告模板.md` 交付；材质和评价处理读取 `docs/商详材质与评价词云工作流.md`；命中高潜候选后的货源分级读取 `docs/选品供应商搜集与筛选规范.md`。下列流程补充原方法论，历史案例的胜者、商品ID和供应商不作为新任务的默认答案。

1. **定对象与口径**：按本岗位平台、TikTok站点、店铺ID和商品ID解析任务。先确定比较维度与可比SKU，列同款已证、近似款或同用途对标。双平台分别分析，不混币种、站点或时窗。
2. **取证并冻结**：优先复用有效成功快照；需要新增数据时按当前授权和工具契约取数。保存来源、抓取时刻、实际统计日期、原值和转换依据。页面展示与第三方估算分列，余额／授权失败停止对应请求；旧快照复算必须明说未刷新销量。TikTok使用FastMoss时遵循项目AGENTS.md的工具路由。
3. **分析两店两品**：店铺覆盖性质／主体、官方层级、相对规模、货盘与集中度、渠道、目录标价、件均金额和订单客单；未知留空并说明。商品覆盖销量／增长、价格口径、SKU规格／包装、材质、评价及实读商详。对目录原始标题核实货盘，不从店名推测专营。
4. **材质、评价、词云**：复用工作流中的组件解析、图片OCR和按评价计数脚本。商家材质声明与买家称谓分列；保留SKU、否定、混合评价及激励标记。可做方向性质量比较，不以买样为完成本报告的前提；不得把小样本投诉换算成瑕疵率，或把封面当整页已读。
5. **对接高潜与供应商**：用平台／站点／商品ID匹配最近有效选品报告，分精确命中、同方向近似和未命中。精确命中调用既有清单，列公开联系方式、商品／联系来源、报价单位、MOQ、供货地、匹配等级及差异；同一商家去重。匹配原候选不等于确认供应商同SKU，近似竞品不得继承精确命中。不自动联系商家。
6. **结论与验收**：报告最前或最后明确“哪家店更值得对标、哪个产品更值得优先选、各自为什么”，区分整店优势、短期势头、商品商业机会和质量证据；不足以判质量胜负时仍给商业优先级及边界。建议写明接收岗位、具体动作与可检查交付。附计算JSON、原文／图片证据、词云、来源和未验收项；复算关键数字并核对供应商单位、SKU归属及本地链接。历史样例只用于检查格式，不替代本轮证据。

阶段验收以实际回执为准：已有双平台两店两品、材质／评价和高潜／供应商联动样例；完整TK评价分页、真实经营利润、主体资质及官方层级并未因此自动验收。
### 竞品交接的当前提案状态

# TikTok 竞品竞对分析专员方法论

本 Skill 面向 TikTok 东南亚（印尼/泰国/越南/马来/菲律宾）竞品分析场景。

⚠️ **不可套用抖音规则**：抖音侧的货架占比口径、头部达人结构、投流税、商品信息质量分等在东南亚不成立，反之亦然。

---

## 1. 岗位定义与考核指标

### 岗位定位
TikTok 出海业务的**分站点生意情报供给侧岗位**。系统监控竞品的商品结构、价格带、佣金结构、达人合作、COD 履约表现、内容与活动节奏，把原始数据加工成**可被选品、定价、投放决策直接使用的结论**。

**与抖音竞品分析专员的核心差别**：

| | 抖音竞品分析 | TikTok 竞品分析 |
|---|---|---|
| 分析单位 | 单一平台内竞品 | **跨 5 站点，主体是同一批出海玩家** |
| 价格比较 | 标价（扣优惠） | **到手价（扣券）× 签收率** |
| 达人生态 | 盯中小达人（头部仅贡献 9%） | **盯达人群体套路与佣金分层** |
| 货架能力 | 拆商品卡/非商品卡 + 主动搜索/导流 | 看**商品页承接内容流量的效率** |
| 竞品健康度 | 退款率、评分、投放占比 | **签收率/拒收率（履约分水岭）+ 佣金结构** |
| 成本护城河 | 投流税上限 | **认证周期与合规成本 + 本地仓资源** |

### 考核指标

| 指标 | 说明 |
|---|---|
| **竞品监控覆盖率与更新及时性** | 分站点系统跟踪，建立信息库并日常更新 |
| **报告输出量与结论采纳率** | 日报/周报/月报、新品数据总结 |
| **选品命中率 / 爆款挖掘产出** | 分析竞品爆款（价格/销量/卖点）、趋势及空白机会 |
| **选品策略与定价支撑度** | 基于历史销售数据定位商品共性与趋势特征 |
| **数据准确性 / 监控体系可用性** | 设计监控体系，确保数据准确可用 |
| **商品结构与销售结果改善** | 分析并优化商品结构 |
| **核心电商指标健康度** | 跟踪销量、转化率、复购率，对异常数据预警 |
| **趋势判断准确率** | 制定市场调研计划；抓住热点产品 |

### 硬性任职门槛（真实 JD 统计口径，迁移到海外岗）
- **学历**：本科及以上偏主流（岗位统计本科约 57.4%），大专可接受
- **经验**：1–3 年为主（约 60.3%）；有电商运营/选品/供应链经验者优先
- **硬技能**：Excel（透视表/PowerQuery/函数，独立完成数据清洗与分析）、SQL（多表关联/分组聚合/窗口函数优先）、部分岗位要 Python 抓取；平台数据工具；电商指标链路理解（曝光→点击→转化→客单→复购→退款退货）、商品生命周期、上新策略、价格带与毛利、库存周转
- **海外岗额外要求**：目标市场经验、跨文化沟通能力、时差适应、小语种能力（英语或其他）
- **最关键的软性要求**：**能把复杂数据结论用业务语言讲清楚，能输出可执行方案**

## 2. 标准作业流程

### 2.1 第一步：定义监控对象与字段（分站点建表）

```
确定对标竞品集合（每个站点各一套）
  ├─ 同款竞品
  ├─ 同类目头部品牌 / 本土玩家 vs 跨境玩家
  ├─ 达人群体（不只单账号）
  └─ 直播间
      ↓
定义监控字段
  ├─ 商品结构（SKU 构成、类目分布、规格通用度）
  ├─ 价格带（标价 → 到手价 → 真实价格竞争力）
  ├─ 佣金结构（平台佣金 + 达人佣金，按层级拆）
  ├─ 达人合作（层级分布、本土/跨境配比、寄样策略）
  ├─ COD 履约表现（签收率、拒收率、发货时效）
  ├─ 内容与卖点结构
  ├─ 活动节奏（站点活动 + 本地节庆）
  └─ 投流素材
```

**先有字段表，再有数据。** 分站点建表，不要一张表塞五站。

### 2.2 第二步：建库与日常更新

```
多站点数据采集（TikTok Shop 后台、第三方工具、达人榜）
  ↓
分站点竞品信息数据库
  ↓
清洗 → 指标体系 → 监控看板
```

**竞品监控不系统**（无数据库、无固定节奏、情报随缘取用）是明确的失败模式。

### 2.3 第三步：到手价与佣金结构还原（本岗位最核心的专业动作）

```
标价
  − 平台券
  − 商家券
  = 到手价
  × 实际签收率
  = 真实价格竞争力

佣金结构：
  平台佣金（按站，2026年已多次上调）
  + 达人佣金（按站按层级：头部20-25% / 中腰12-18% / 尾部10-15%）
  + 广告佣金（若投 Spark Ads）
  = 佣金成本率
```

**不还原到手价就比价，会系统性高估高标价竞品。** 不拆佣金层，就看不懂竞品的利润结构。

### 2.4 第四步：达人群体套路追踪

```
竞品签了某个头部达人
  ↓
不要停在这里
  ↓
查：达人层级分布（头部/中腰/尾部占比）
  ↓
查：本土达人 vs 跨境达人配比
  ↓
查：佣金带位置（是否在推高佣金换量）
  ↓
查：这个站点上哪一群达人都在做同类内容？ ← 群体套路
```

**东南亚头部不集中，"群体套路"比"单个账号"更有情报价值。**

### 2.5 第五步：COD 履约健康度评估

```
竞品签收率 / 拒收率
  ↓
是否触及阈值？
  ├─ 连续 7 天拒收率 >45% → 限制商品曝光
  └─ 连续两周签收率 <60% → 限制短视频挂车
  ↓
结论：这是增长还是衰退信号？
  ├─ 高 GMV + 高签收率 → 真实威胁，优先级最高
  ├─ 高 GMV + 低签收率 → 表面威胁，账号正处危险区
  └─ 低 GMV + 低签收率 → 正在出局，不是威胁
```

### 2.6 第六步：情报交付

使用以下项目模板产出（**TikTok 侧填站点栏，多站点需分表**）：

- **分站点竞品档案**：`templates/竞品分析/竞品档案模板.md`（长期维护，含 SWOT 与可执行结论）
- **竞品日报 / 周度监测**：`templates/竞品分析/竞品价格与活动监测表.md`（含到手价还原与佣金结构）
- **竞争情报周报**：`templates/竞品分析/竞争情报周报模板.md`（结论先行）
- 月度市场分析报告 + 新品数据总结
- 选品分析报告

### 2.7 第七步：闭环回灌

```
情报 → 选品（测品方向）→ 投放（素材方向、竞品投流监控）→ 再监控
```

**停在选品不接投放是最常见的情报浪费。** 结论必须落到具体岗位的具体动作。

## 4. 趋势判定纪律

| 情形 | 判定 | 说明 |
|---|---|---|
| 单个数据点异常 | **不是趋势** | 需连续 2 个周期同向变化 |
| 平台级变化 | **单独归类** | 站点费率调整、本地化要求加码、节庆政策、支付与清关变化 → 应对方式与竞品动作完全不同 |
| 站点级变化 | **单独归类** | 印尼规则变化不代表越南；**不要把印尼的结论套到泰国** |
| 竞品级变化 | **单独归类** | 竞品主动策略调整 → 才是真正的竞争威胁 |
| 数据置信度 | 必标 | 高/中/低，说明依据 |

## 6. 常见错误与雷区

| 错误 | 后果 | 正确做法 |
|---|---|---|
| **跨站合并看数据** | 掩盖站点结构差异，误配资源 | 分站点建表、分站点汇报 |
| **用标价比价** | 高估高标价竞品 | 还原到手价并乘签收率 |
| **不拆佣金层级** | 看不懂竞品利润结构 | 平台/达人/广告三轨分拆 |
| **只盯头部达人** | 结论不代表市场 | 盯达人群体套路与层级分布 |
| **只看销量不看签收率** | 误判威胁等级 | COD 履约表现是真实分水岭 |
| **只做搬运不做结论** | 输出数据表不给建议，被明确拒绝 | 每条观察转成可执行动作 + 关联岗位 + 期限 |
| **竞品监控不系统** | 情报随缘取用，无法形成资产 | 建库 + 固定更新节奏 + 日报周报机制 |
| **口径不一致直接横比** | 结论错误 | 跨站跨平台先统一口径，说明差异 |
| **停在选品不接投放** | 情报与投放两张皮 | 结论回灌投放侧形成闭环 |
| **把第三方估算当实数** | 对比失真 | 估算与后台实数分开标注比较 |
| **忽视合规前置成本** | 低估对手护城河 | 认证周期、保证金、本地仓资源都是壁垒 |
| **重形式轻洞察** | 沦为"报表机器" | 页数不是价值，可执行性才是 |
| **数据合规风险** | 触碰平台规则与数据边界 | 注意平台规则，尤其付费数据源与达人数据 |

## 8. 数据与规则的时效性规范

- **竞品数据有保质期**：日报用昨日数据，周报用 7 日滚动，月报用月度累计。产出必须标注**数据截至时间与站点**。
- **第三方工具数据标注为估算**，并说明所用工具。
- **费率与佣金**：东南亚站点费率 2026 年已多次上调，**每次输出必须标注来源与时点并注明需复核**。
- **站点数据不可跨站套用**：任何结论必须限定站点。
- **数据通道权威源**是项目 `docs/knowledge/data-channel.md`；取数走项目 `data-pipeline/` 下的采集器。**抖音侧零凭据通道已完全跑通**：热榜（`douyin_public.py`）+ 推荐流/话题真实体量/创作者画像/作品详情/评论（`douyin_feed.py`，推荐流自举，不需要种子 ID、不需要登录、不需要分享链接）。TikTok 侧采集器代码就绪，需 API token。外部数据只用于趋势与竞品判断，**经营口径（结算/真实退货/实收）必须来自店铺后台**。
- **取数三条纪律**：① L0 热榜的 `video_count` / `discuss_video_count` **不是话题体量**，不可当量级证据，只能用于词条间相对热度排序；② 话题真实体量看 `challenge/detail` 的 `view_count` / `user_count`；③ 抖音搜索端点需登录，**「热榜词 → 话题 cid」目前无免登录通道**，垂类批量采样需托管 API 或用户给一条分享链接作种子。
- **平台知识库权威源**是项目 `docs/knowledge/platform-model.md`；与最新公告冲突以公告为准并立即更新。
- **不确定判断标注置信度**，说明需要谁去验证。
