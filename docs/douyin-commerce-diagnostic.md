# 抖音经营诊断对照

适用于抖音负责人复盘和商城商品卡、搜索、推荐漏斗诊断。根据本次决策选用所需检查，沿用岗位现有模板与输出字段。

1. **先核可比性。** 指明要回答的问题与比较基线。对关键指标核对同一平台、店铺、商品／SKU、入口、分母、时区、统计窗口、可售天数和活动阶段。区分支付、结算与退款成熟口径。检查总量与相同范围内去重后的明细能否对上。缺项标未知，分母为 0 的比率留空，可核实的 0 保留。两份记录冲突时保留各自的原值和引用，说明是否能解释差异；未解决的冲突只限制受影响的指标。外部估算只作线索，店铺经营结论使用同口径的后台或获准导出。
2. **定位哪一步发生变化。** 在可比数据上给出方向、变化和有效分母，再沿岗位现有的归因顺序或漏斗定位。区分已观察变化、可复算结果和待验证原因。拆开自然搜索入口、商城推荐和内容导流，避免跨入口混算。活动或广告与变化同现时，写作相关线索；估计增量需要可信的对照、留组或其他可比设计。
3. **选最省的一步验证。** 有竞争解释时按证据强弱列最多三条。每条用现有报告写明支持信号、能推翻它的反证，以及一项能解决判断的最小动作。信息不足时可直接交接补证。给负责人、所需证据、比较窗口和继续／停止条件。已有独立充分证据的低风险动作可继续，例如对照素材、小样本复核或离线草拟单变量试验；缺少某项数据只暂缓依赖它的动作。
4. **把诊断结果带回原有门禁。** 诊断输出可以是建议、补证或送审。价格、叠券、活动、库存和投放仍按各自已批准的门禁处理。价格证据不足时保留待审，已知跌破底价等失败按原协议拦截。推荐入池、评分、促销比例等门槛须有适用的版本化来源；历史数字、平台建议价或竞品价在来源未对齐时只作线索。真实变更由原有授权流程决定。
