# 双平台短视频编导可拍脚本工作流

2026-11-09。沿用 `douyin-video-director` / `tiktok-video-director` 原岗位、完整私有Skill和 `templates/短视频编导/` 三模板。该流程验收当前商品的脚本设计能力，实际试拍、发布和经营效果分别验收，不用历史冻结男装报告替代玩具业务证据。

用户后续生产方式已明确为**实拍素材自动混剪**和**产品素材图自动生成视频**。下文的可拍稿是设计基础，执行时按 `双平台短视频自动成片双路径工作流.md` 转成素材时间线或图生镜头指令；有合适现成实拍不要求重拍。两条路径都要验实际成片，当前文本通过不代表自动成片已经通过。

## 入口与输入

先运行对应Skill的 `scripts/resolve_project.py`，读取原岗位、完整Skill、平台模型、数据渠道、JD和三模板。记录读取时的来源与SHA256。原Skill里的平台政策、费率、搜索倍数、限流识别率、COD和达人排期数字都不是本轮现行规则；无法实时证实时保留为历史，不写入确定性产品承诺。

本轮结构来源为 `docs/provider-evidence/turbo-upgrade-2026-11-09/` 的V4八段、要素库和编导交接。商品事实使用既有真实详情、SKU目录、商详/评价证据，不把竞争者作品的广告词自动转到我方商品。只为重新写稿不重复调用付费数据接口。

抖音发布挂车ID单独判定：必须有作品aweme_id到目标product_id的明确记录，或有已核映射的promotion_id；变体SKU非门槛。同店账号、标题、with_goods、广告类型、商详演示及请求参数回显均不够。本轮独立审计与补采见 `docs/provider-evidence/director-acceptance-2026-11-09/`，当前没有签目标商品发布硬链通过。

**先过商品入口筛选，再查挂哪件商品。** 对作品记录“已证有商品入口/本次已证无入口/未确认”，并保留观察面、时间和来源。可核的本条视频商品锚点/跳转记录，或前台可打开的购物入口，才能用于确认；仅状态标记作线索，空anchors不直接判无。确认无入口或未确认时不继续消耗接口额度追目标商品ID，可保留为结构研究样本。现有 `with_goods` 在 `aweme_detail.status`，A/C=true、B=false；B移出挂车补采队列，A/C仍待实际入口核验，不能把标记升级为目标商品绑定。

已验证的新解析分支是 `aweme_detail.anchor_info.extra`：它可能是JSON字符串，须解码后读每条商品的 `product_id`、`promotion_id` 和 `product_detail_schema` / `jump_schema`，并核同一作品上下文。用户汽车对照即从此取得已核商品 ID，可签API级入口/绑定；页面点击仍未做。schema里的 `item_id` 在该例是视频ID，不当商品ID。原字符串JSON pointer与解码后pointer分列，不把字符串直接当数组访问；不能仅检查promotions/anchors就签无商品。

同一份真实回执已同时给出商品入口与对应ID时，可一次完成两关，不为形式再调一次接口或强制补UI点击。API级绑定、UI可点击性与实际销售效果仍分别记录。

## 商品事实卡

每个研究商品建立一张卡，字段至少包括平台/站点、商品ID、店铺或seller ID、来源文件/抓取时点/JSON pointer/SHA256、标题和目录选项原文，并分四种事实范围：

1. **实际返回的目录信息**：确认页面或接口这样显示，不等于我方实测；尺寸、装数和颜色不跨商品或选项转用。ID按字符串保留。
2. **素材可见内容**：来源时点和观察帧，不等于我方拥有相同实物或连续物性测试结果。
3. **商家声称**：材质、适龄、检测、安全、疗效、价格优惠、库存和水洗等广告表达，未经独立商品证据不能写为我方承诺。
4. **我方生产事实**：实物、规格测量、包装、价格库存、资质、商品承接、履约、素材权利。没有就用null/待核，不能把目录选项当已经到货。

研究商品ID不是我方已上架ID；发布承接字段单列，未配置保持null。准备样品可以指定一条真实目录选项作为目标，但必须标待到样核对。

## 选题、钩子和脚本

每平台先做3个结构不同的完整脚本，覆盖两目标商品。每商品至少3个完整首3秒钩子，各自给镜头动作、实际录制台词/字幕和独立评审；不是只写“痛点型/反差型”。主钩子与正式分镜一致，替换钩子时其余内容固定，不能把不同完整选题混成单变量A/B。

每稿只保留一个核心信息和一个明确CTA。分镜从0秒连续到总时长，首镜单列0—3秒；逐镜写机位/景别、道具与具体动作、完整口播及字幕、声音、商品露出、实拍要点、合格/补拍条件。剪辑不能加速、倒放或换件来伪造回弹和性能。

本轮设计偏好为抖音15—45秒、TK15—30秒竖版；它们是制作方案，不是平台现行时长规则。内部口播负载粗检采用中文不超过5字/秒、印尼语不超过3词/秒，超出要改句或重分时间。它只是规划检查，不冒充演员实读、母语审稿或录音验收。

录制文案中不得保留“[价格]”“待补材质”等占位符；事实缺失时去掉相应话术或改用可见演示。不能虚构亲身购买、家庭证言、质量保证、倒计时和抢购；历史视频的26k、优惠及重量印字不当我方信息。

抖音提供3个搜索词候选，但不称已定坑。TK印尼给原语台词/字幕和中文含义，明确语言/货币单位/场景人物/文化符号四层状态；无母语者时标AI拟稿、母语确认待做。hashtag未实时查证就标候选，不叫当前热门。支付及履约不明时从文案中删除承诺，不套用旧Skill的“仅COD”。

## 拍摄交接与验收层级

拍摄清单按脚本/镜号列出样品身份、包装、道具、成年出镜或手部、机位距离、背景灯光、收音、拍摄顺序/次数、素材命名及剪辑交接。新拍素材只用我方实物和获准素材；研究原片不直接搬用。

| 层级 | 本轮验收对象 | 不得提前勾选的内容 |
|---|---|---|
| 脚本设计 | 有来源、可执行分镜/物料/动作、能读完的话术、明确事实边界和测试方案 | 到样、实拍、母语签字、发布、指标提升 |
| 实际试拍 | 样品与选项一致、动作安全可执行、实际时长/收音/画面/字幕通过 | 未执行的现场清点或成片质检 |
| 上线与效果 | 我方商品承接和发布条件确认、获准上线、固定观察窗口、真实后台数据 | 缺实际数据的完播/CTR/CVR/ROI、爆款或盈利结论 |

原Skill商品确定性不足时不排正式拍期；可以交付可拍设计，并把开拍与发布门槛保留为待办。局部事实未知只限制相应话术，不否决所有设计能力。TK母语确认仍是正式录制/发布前的待办，不把AI拟稿伪装成母语者签字。

脚本以JSON为内容源，渲染MD和清单；检查连续时间、钩子数量、逐镜口播负载、来源指针、平台差异和重复渲染。另由负责人做实际内容审稿；字段齐全不等于文案好或事实真。测试计划列变化项/固定条件/指标/观察窗与混杂因素，真实结果均null。没有发布授权时只设计，不自动投放或外联。
