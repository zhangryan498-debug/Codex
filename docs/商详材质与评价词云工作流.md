# 商详材质与评价词云工作流

用于抖音、TikTok 竞品岗的方向性质量对比。输入两款商品 ID；输出商详文本／图片证据、去重评价、带原文的关键词频次、每品词云和对比结论。本步骤不要求买样。商家声明、买家反馈、分析推断分别陈述；不把文本分析写成真实成分或安全认证。

## 当前可用接口与已修解析

- 抖音：Just One `douyin-ec/get-item-detail/v2` 的 `data.model.product.product_base.big_imgs` 是商详图片；`get-item-comments/v1` 以 `itemId,page` 翻页。本轮每品最多 5 页，缓存优先，按评价 ID 的哈希去重。已验证两款最近若干页，不代表全站商品都可取全量。
- TikTok：Just One `tiktok-shop/get-product-detail/v1` 的 `data.product_data.page_config.components_map` **本轮是列表**。按 `component_name=product_info` 找 `component_data`，其中 `product_info.desc_blocks` 提取 `text` 与 `ul/ol.content`，图片在 `image.url_list`。不要重复收集 `rich_text`，以免把同一文案计算两遍。材质标识从商详及 OCR 搜索；未知成分保留未知，不能用“慢回弹”倒推 PU 或硅胶。
- 同一 TikTok 组件的 `review_info.product_reviews` 提供展示评价，`review_ratings.rating_result` 提供全量累计星级分布。记录 `has_more`、`total_reviews`、`is_verified_purchase`、`is_incentivized_review`。本轮每品只返回 3 条展示评价；不能凭 `has_more=true` 自行编造分页参数。地区参数可选 ID/TH/VN/MY/PH，**本轮只验了 ID**。
- 同一组件的 `shop_info` 提供店铺基本页面字段，归一化到 `shop_profile`：店铺 ID／名称、评分、页面累计销量、在售数、返回时的粉丝／视频数，以及带可读名称的 `shop_exp_scores`。本轮补读到两店 29／274 个在售、89%／90% 的48小时发货展示指标和100%／93%的24小时响应展示指标。保留页面日期与字段来源，不同于 FastMoss 的检索数量或销售估算；不将这些字段推断为主体性质、官方等级、独立售后审计或实际经营后台值。
- FastMoss `product_review_list` 曾在近 28 天、累计、去掉时间筛选及 CLI 原始 RPC 中仍返回空列表。本轮用 Just One 展示评价兜底，FastMoss 正文分页未通过验收。空列表不等于零评价；额度与回执单独留档。Just One 当前[官方目录](https://docs.justoneapi.com/zh/api/tiktok-shop/)未列独立商品评价分页接口，尚未验证其它旧版。

## 可复用命令

在项目根运行，使用 `.venv/Scripts/python.exe -X utf8`。在线采集从 `JUSTONE_API_TOKEN` 或隐藏输入读取凭据，不写入文件。每个平台每次限 1–2 款、抖音最多 5 页，失败或无新评价时停止。旧缓存需要更新时使用新的日期目录，保留旧快照。

```powershell
.venv/Scripts/python.exe -X utf8 scripts/collect_review_evidence.py --douyin-id <A商品ID> --douyin-id <B商品ID> --tiktok-id <A商品ID> --tiktok-id <B商品ID> --region ID --output-dir work/review-evidence --max-pages 5
.venv/Scripts/python.exe -X utf8 scripts/download_detail_images.py --input work/review-evidence/collection-summary.json --output-dir work/review-evidence --max-images 40
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/ocr_product_images.ps1 -ManifestPath work/review-evidence/image-manifest.json -OutputPath work/review-evidence/all-material-ocr.json
.venv/Scripts/python.exe -X utf8 scripts/analyze_review_evidence.py --input work/review-evidence/collection-summary.json --ocr work/review-evidence/all-material-ocr.json --output-dir work/review-analysis
```

`--cached-only` 只从采集缓存重建，不读取凭据、不请求接口。`--seed-directory` 可复用已有 `*-detail.json`、`*-reviews.json` 第 1 页；混合不同时刻页面需要披露时间与重复行。`--labels` 可传商品 ID 到展示名称的 JSON。图片下载器缓存优先、每品最多 40 张、每张最多 12 MB、4 路并发，检查 `image-manifest.json` 的失败项与覆盖率。

若两款均没有返回商详图片，跳过 OCR 命令，分析时不传 `--ocr`；仍可处理商详正文和评价。没有取回图片须列为覆盖缺口。

OCR 依赖 Windows PowerShell 5.1 和已安装的 `zh-Hans-CN` 识别语言，不能用 PowerShell 7 直接加载 WinRT。保留图片 SHA256、原始 OCR 与行号；中文字符间空格只在匹配时归并。图片 OCR 不保证无误，关键材质对照原图复读。本轮 63 张全部下载并完成 OCR；TikTok A 的印尼／英文商详辅以图片目视复核，未识别成分不证明全页绝对没有。

词云依赖锁在 `interface/review-analysis-requirements.lock.txt`，字体默认 `C:/Windows/Fonts/msyh.ttc`。输出 JSON 保留评价哈希、SKU、星级、原文和每个关键词命中依据，不含买家姓名／头像／账号 ID。

## 统计与结论规则

1. 区分总评数量、抽取行数、按 ID 去重数、非空正文、有效正文、命中质量关键词正文。空评不进入分词；纯标点、单字母和明显无关文本剔除并保留原因。泛泛“好”可以计为有正文，但不硬提质量结论。
2. 当前规则库服务捏捏乐等低成本小玩具，归并气味、漏液／裂缝／起皮、硬度、手感、柔软、回弹、外观和价格等关键词。印尼语保留原文：`lembut=柔软`、`elastis=弹性`、`wangi=香味`、`tebal=厚实`、`silikon=买家称硅胶`。新类目先审视原文并扩展规则，不能把当前小词典宣称为全类目通用分析。
3. 统计单位是**提到该归并关键词的评价条数**。同一条多次重复只计 1，不同维度可以重叠，不能把各关键词计数相加作为评论人数。无异味、不会漏液与没有别人说的那么硬等保留否定；五星也可能含破损，需保留混合表述及使用情境。
4. 商家正文与商详 OCR 只进入材质／卖点证据库，不混进买家评价词云。买家写“硅胶”仍是主观称谓；`slow rising glitter` 是性能／外观描述，不是明确聚合物成分。
5. 词云红色为风险、绿色为正向反馈、蓝色为描述。字号各图独立适配，横比用精确计数和样本分母。图中文字是归并词，不一定是买家逐字原话，原文可从 JSON 回溯。
6. 抽样窗口不齐、展示排序和激励标记限制结论。本轮抖音正文不足 30 条，TK 仅 3 条且全部有激励标记，方向参考即可。可以输出“风险线索更集中／值得优先排查”的判断，不能输出真实瑕疵率、材料毒性或确定的质量排名。

复验：`python -X utf8 -m unittest discover -s scripts -p test_review_evidence.py -v`。这检验组件解析、去重、否定、混合评价、隐私字段清理和材质未知处理；配合真实接口回执与词云目视验收。
