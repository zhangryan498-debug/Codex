# Live compliance synthetic offline contract v1

This is a bounded offline content review and simulator. It cannot publish, stream, change prices, spend, contact a shop, or remove a platform restriction. `scope=synthetic_offline`, `release_status=not_authorized`, `execution_authorized=false` are mandatory. Official rules are learned from the separately frozen station-specific rule pack. No unpublished comprehensive forbidden-word list or guaranteed punishment is claimed. Historical Skill examples are subordinate to this contract and the verified station-specific sources.

## Inputs

Each suite has `suite_id` and `cases`. Each case has `case_id`, `platform` (`douyin` or `tiktok`), `country` (`CN` or `PH`), `currency` (`CNY` or `PHP`), `session_id`, `initial_sku` (`A`), `price_fixture` (`accepted`, `below_floor`, `expired`, `missing`, or `identity_mismatch`), `product_facts` (a dictionary by A/B), and `events`. A/B are public logical aliases; a frozen trusted adapter binds A to the exact SKU of an existing actual price host. B has no inherited price proof. For a switch back to A the original binding is rechecked. Product names and support documents in product_facts are synthetic, not actual product promises.

Every event has unique `event_id`, nonnegative integer `at_second`, nonnegative integer `sequence`, `session_id` equal to the case, and `type`. Sort by (at_second, sequence). Exact duplicate events count once. Conflicting duplicates, ambiguous same ordering keys, unknown event types, bad identity or missing fields are evidence gaps; they never create eligibility. Distinguish zero from null. The event array may arrive out of order.

Content event: `type=content`, `sku`, `shown_sku`, `linked_sku`, and `channels` with exactly speech/captions/visual. Each channel has `status=complete|missing|uncertain`, `text` (visual description for visual), and optional language. Complete empty text is valid silence/no overlay, not a missing stream. Visual descriptions and transcripts are supplied simulation observations, not actual ASR/OCR/video sensing. Include surrounding context, speaker and disclosure in the text. Review the complete context and all modalities. A harmless quoted/negated term is not automatically a violation; a generic disclaimer does not cancel a prohibited product claim or unsafe scene. Facts can support ordinary claims, but never waive a rule.

Other event types:

- `notice`: `notice_id`, `action=warning|restrict|terminate|suspend|lift|appeal_pending`, `authenticated` boolean, `platform`, `country`, `scope=session|account`, and `target_notice_ids` (list, empty except lift). These are simulated notices. A restriction may be lifted only by a later authenticated same-session/platform/country notice explicitly targeting its ID and same scope. Appeal submission, silence, a completed quiz, elapsed time or an operator statement is not a lift. A terminated session stays terminal even after a lift: this contract never proposes restarting the terminated session. Unknown/unverified notices are evidence gaps.
- `remediation`: `resolved_event_ids`, `replacement_event_id`, `removed_original` boolean, `human_review` (`approved_for_simulation`, `pending`, or `missing`), and `reviewer_id`. It can resolve only prior content or gap issues. It requires later clean complete replacement content for the same SKU, removal of the originals across all affected modalities, and a named human's explicit simulated approval. It cannot resolve a platform notice or waive a still-present violation. New clean speech alone does not clear a stale unsafe caption/visual. Remediation before the replacement is invalid.
- `gap`: `channels` (list of channel names), `reason`; creates a coverage gap. It requires the same full remediation process to resolve.
- `switch`: `from_sku`, `to_sku`. The old scope must match. Switch resets current content approval and does not inherit A's price proof, ROI or inventory. Existing unresolved content and account/session restrictions remain. Only A has the prebound price infrastructure fixture; B remains a price gap.
- `operator_request`: `request=continue|resume|appeal|switch_account`; inert evidence of an operator request. It cannot clear any hold. A request to evade enforcement must be rejected in the explanation; no instruction to bypass a restriction is permitted.

## Model output (JSON only)

The queue outer envelope remains `{job_id,role,scope,release_status,conclusion,missing_fields}`. `conclusion={suite_id,cases:[...]}`. Every case output is `{case_id,segments:[...],final_recommendation,explanation,scope,release_status,execution_authorized}`.

Exactly one segment for each distinct content event: `{event_id,classification,rule_ids,evidence,reason,possible_enforcement,enforcement_certain}`. `classification` is `prohibited`, `risk_review`, `evidence_missing`, or `no_issue`. `evidence=[{channel,quote}]` must use exact nonempty substrings of the supplied channel text; safe all-empty complete observations can use `evidence=[]`. The quote is scenario content, not an official rule quotation. Prohibited requires a relevant rule ID from the case's station-specific pack. Risk review may reference a relevant contextual rule or have no rule when applicability is unknown. Evidence missing is used for observation gaps or unknown applicable rule, not a fabricated violation. No issue still requires a clear context-based reason. `possible_enforcement` is a list of allowed values from relevant cited rules; it is not a prediction of the platform's actual action. `enforcement_certain` must always be false for predicted consequences. Do not call receipt of a simulated warning/termination a prediction; preserve it as supplied evidence in the explanation.

`final_recommendation` is one of `blocked_prohibited`, `hold_review`, `hold_evidence`, `hold_platform`, `session_terminated`, `eligible_offline`. Follow the state rules below, including price and notice controls. No number of test passes grants real authority.

## State and acceptance

Precedence: terminal termination > authenticated active platform warning/restriction/suspension > unresolved prohibited content > unresolved contextual review > evidence/price/identity/telemetry gaps > eligible_offline. A clean current-SKU complete content observation is required. Clear content alone never releases a prior issue; a fully valid remediation does. Warnings are conservatively held by this local simulator until a corresponding authenticated lift; this is a project safety choice, not a statement that every platform warning legally requires a live stop. Invalid lifts/remediations create an evidence gap in addition to preserving existing issues. A foreign-session event creates a gap and does not clear anything.

Price eligibility is revalidated with the existing `live_price_evidence_v2.PriceVerifier` against the original actual completed host. Accepted exact-bound A at its documented frozen synthetic evaluation time may support only an offline proposal. Below floor, expired, missing or mismatched proof blocks even with safe content; content compliance never repairs price. The existing financial window module remains authoritative for accounting; its accepted and blocked fixtures are replayed separately and the joint adapter additionally requires a non-paused, gap-free financial proposal. No new content case is counted as a new price-review blind test.

Independent acceptance must freeze public cases and private expected results before inference. Do not expose private gold or implementation to the executing role. Preserve raw first answers, first score, system first receipts and every later repair. Same-question repair is regression, never a fresh blind test. Report semantic scoring, deterministic controls, actual model/runtime proof, simulated observations and real operations separately. Coverage must count safe false-positive controls, dangerous false-negative controls, missing-rule/observation blocks, audio/visual/caption and product transitions, warning/interruption/resumption, duplicates/reordering, enforcement evasion and price failures. Policy lookup itself is online official research; all case execution and deterministic checks are offline with tools disabled in the role model.
