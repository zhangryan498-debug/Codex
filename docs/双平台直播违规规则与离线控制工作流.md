# 双平台直播违规规则与离线控制工作流

本入口用于抖音国内与 TikTok 菲律宾的合成直播内容复核、模拟通知和恢复提案。沿用原直播岗位、完整 Skill、队列及原价审基础设施，并显式预载新的公开协议和官方规则包。所有结果仍为 synthetic_offline / not_authorized，不能开播、改价、投放、发布、申诉或连接店铺。

## 官方规则学习与适用边界

先读 `docs/live-compliance-contract-v1.md`、`docs/live-compliance-rule-pack-v1.json` 和 `docs/live-compliance-source-scope-note-v1.md`。首轮之后新增的PH CPL任务另读 `docs/live-compliance-rule-pack-v2.json`、`docs/ph-live-cpl-contract-v1.md`、`docs/ph-live-cpl-clarification-v1.md`；新专节优先而不回写首轮。规则包保留官方标题、直接链接、显示日期、适用对象、读取方式、上下文边界和未核实项；`explicit`、`contextual`、`capability`分开。没有公开穷尽禁词表，也没有某词必然下播的映射。一般处置范围须附引本平台通用管理／执法来源，不能把旧版或不完整细则的类别直接说成现行明确违规。

抖音主要使用2026年电商创作者正式规则；2024年公开直播规范只作明确限定的历史支持。新版第三方交易细则未完整取得、部分日期展示冲突仍保留。PH 使用明确菲律宾适用的 Shop 页面或其有据可查的官方引用链；不能移植印尼、美国的词表、费用、扣分或处罚阈值。全球 TikTok LIVE 正文读取受限与 Shop 商业推广规则分别报告。CHR 测验恢复点数在同页有矛盾，不编码任何一值。

这些文件是本轮离线入口的优先补充，未批量改写原 Skill 的全部历史政策数字；旧岗位原文不构成新授权或现行规则保证。

## 输入和输出

输入是有时间、顺序、场次、商品及渠道身份的合成事件；口播转写、字幕和视觉描述均为已提供的模拟观察，不证明真实 ASR、OCR 或视频感知准确率。角色模型须结合完整语境及商品事实，区分明确禁止、人工风险、证据缺失和无问题；否定、引用、正常儿童商品演示等不能只按词命中。免责声明不能抵消仍存在的虚假承诺、危险画面或不一致商品。

每个内容事件一份模型判断，引用原渠道的精确片段和同站规则。系统另核身份、完整覆盖、原生布尔、来源、通知与整改，不把结构检查当语义正确。可能处置只能是有据的范围，不能声称后台已处罚或某次触发必然如何。

模拟通知保留 ID、场次、站点、作用域和认证状态。提交申诉、完成测验、时间过去、换话术、换账号均不能解除限制。终止的同一场次不复活。恢复提案要求与原通知匹配的正式模拟解除凭证、警告后的完整清洁观察和必要的具名模拟人工复核；本地保守暂停规则须与平台明文处罚条件区分。

整改须同时移除各受影响渠道的旧内容，并绑定后续同商品、完整无问题的替代观察。新口播不会自动清除仍残留的旧字幕、画面或商品链接。重复完全一致事件去重，冲突保留兄弟原文并阻断；乱序按明确时间与序号处理。缺失或模糊身份不能被默认值修成安全。

## 价格、财务与执行限制

内容合规、有效通知状态、完整观察、正确商品、实际价审凭证与财务门禁必须同时成立。价格复用 `live_price_evidence_v2.PriceVerifier`，按原 caller、实际已完成 host、站点、SKU、数量、版本和冻结微秒时钟核对。破价、过期、缺凭证或错身份都不能由安全话术放行。A/B 是公开逻辑别名；B 不继承 A 的价格、账本或库存。

已有逐窗模块继续负责累计／窗口、成熟／暂估、退款、库存、预算和增量收益。此轮内容案例复用明确标识的已知合成财务基础设施，独立重放原24个财务场景；不算新的财务或价格盲测。若将基础设施模板映射到新的模拟场次，须保留原始来源、显式派生映射、未变金额和新旧哈希，不能把旧真实业绩移入新场次。

## 入口与证据

`scripts/run_live_compliance.py` 提供有限次 infrastructure / prepare / run / host 阶段。prepare 在该次调用打开输入前记录实现、规则和依赖哈希，run 使用原队列与两个原直播岗位，模型工具关闭，完成后冻结实际首答。首次接收回执保留；最终原36题接收补验入口是 `scripts/run_live_compliance_host_v3.py --first <原始或受控收口目录> --output <新目录> --module live_compliance_review_v2`，直接核对实际调用中的公开输入、阶段和完整派生，不重跑模型。v1/v2失败和CN第5批原strict拒收保留。

`run_live_compliance.py host` 的早期接收方式仅用于历史重现；当前终验采用上述v3入口，不能把早期结构通过当完整原输入绑定通过。

PH CPL独立后续入口为 `scripts/run_ph_live_cpl.py` 的 prepare / run / host；纯控制模块为 `ph_live_cpl_v1.py`，原输入绑定沿用 `live_compliance_binding_v4.py`。此入口预载完整原角色／Skill、相关底座／三模板及当前规则，未复制与该任务无关的招聘长档案。新CPL数据应先由独立作者冻结，不能把旧题另建目录就称新盲测。host重算、字段补验和同题修复不增加新题数。

新CPL的三次实际CLI显式传入仅本进程的 `notify=[]` 并关闭模型工具；日志未见legacy通知执行／错误，不据此推断内部解析配置或整个宿主绝对无外联。窗口和持久配置不修改。若出现未预期的legacy通知日志，入口会停止后续批次，保留已完成原答再核实。

独立作者先冻结公开场景、私有金标及评分器。原 strict 首分、公开协议澄清口径复核、系统首轮、工程预审失败、修复后同题回归和新尝试必须分开。相同题目重测不叫新盲测。来源附引的评分歧义保留原机械成绩另做规范复核，不能改金标消除真实错误。

真实店铺、实播音视频传感器、母语签字、实际处罚／申诉／解除、完整类目规则与长期并发断电均未因本模块通过而自动验收；经营结果仍无真实在线数据。


## 品牌背书视觉一致性静默规则 v2（2026-11-14）

候选识别及语境复核之后、生成用户提醒之前，按[直播品牌背书视觉一致性静默规则-v2.md](直播品牌背书视觉一致性静默规则-v2.md)调用`scripts/live_brand_visual_silence_v2.py`的`evaluate(scope, observation, alerts)`：画面与口播品牌有足够同源同窗证据确认一致时，仅品牌对应/授权核查提醒静默，不逐一索取授权凭证；视觉一致与法律授权状态分开，授权未知内部留存。

品牌不一致、画面不足或冲突不能进入静默；其他独立风险保持提醒，混合风险不可整体删除。该规则不覆盖价审/平台通知，也不改原冻结规则包、首分或原候选。普通旧候选输出不直接当作当前最终品牌提醒。
