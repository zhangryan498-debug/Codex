# 双平台短视频自动成片：实拍混剪与产品图生成

初版 2026-11-09，状态更新 2026-11-10。两个平台继续由原 `douyin-video-director` / `tiktok-video-director` 负责。原有 6 份完整稿和 15 个钩子按文本设计验收。自动成片按两条路径与具体样本分别记录，最新证据和版本见[项目现状表](岗位能力推进现状.md)。

## 两条生产路径

| 项 | 实拍素材自动混剪 | 产品素材图自动生成视频 |
|---|---|---|
| 输入 | 我方已有或获准的商品实拍视频、原声/配音、商品事实卡 | 我方提供或获准的产品图、多视角/包装图、事实卡和风格要求 |
| 编导输出 | 选用素材ID、原片入出点、镜头顺序、字幕/配音、画幅/节奏和钩子版本 | 每镜参考图ID、提示词、运动/场景、产品保真约束、时长与字幕/配音 |
| 执行链路 | 素材整理与标签、镜头/话术定位、脚本匹配、时间线、自动剪辑包装、质检 | 产品图核对、图生视频镜头、产品一致性质检、自动剪辑包装、质检 |
| 可利用的本地基础 | FFmpeg 处理媒体，Large-v3-turbo 转写和定位话术，OpenMontage 执行时间线 | MuseCanvas 0.21.3 内置 Codex 与 Muse Video 生成镜头。OpenMontage 剪辑，CosyVoice 3 可独立配普通话 |
| 当前状态 | OpenMontage 合成素材技术验证通过，获准实拍的选镜、原声、主片与钩子待业务验收 | 两款参考板、双平台圆枕样片及抖音挂件样片已有归档。抖音 CV3 圆枕获用户阶段确认，挂件后段变形及印尼挂件版本未通过 |

产品图路径按实际生成的运动镜头验收。静态图片推拉、平移和字幕组成的样片按图文方案单列。

## 共用输入与脚本字段

保留原Skill、三模板和商品事实卡，额外在制作任务中记录：

- `production_route`：`real_footage_auto_edit` 或 `product_image_to_video`。
- `reference_product_id` 与我方 `publish_product_id` 分开；源素材产品、颜色、包装数量和版本要对应。
- `asset_manifest`：素材ID、本地文件、来源/使用范围、SHA256、商品归属；视频另有时长/音轨/画幅，图片另有尺寸与所示视角。
- 每镜目标时长、完整原语文案/字幕、可用事实及禁用承诺；数字缺失不靠占位符直接生成消费者视频。
- 画幅、目标语言、音轨来源、字幕风格、输出文件名和版本；具体生成接口参数以选定工具的真实契约为准。

实拍路径逐镜补 `source_asset_id`、`in_seconds`、`out_seconds`、原速/连续性要求。素材不足时给出具体缺镜，不随机抓其他商品或用不匹配素材凑时长。

### Windows 本地渲染

首次恢复环境时运行安装脚本。它校验 Gyan FFmpeg 9.0.2 发布包及固定提交的 OpenMontage 源文件，将运行时放在项目 `work/openmontage-runtime`。渲染进程从这里加载 FFmpeg 与 ffprobe。OpenMontage 只调用本地 `VideoCompose.compose`。

```powershell
.\.venv\Scripts\python.exe scripts/setup_openmontage.py
.\.venv\Scripts\python.exe scripts/render_real_footage.py work/商品任务/主片.json --output-dir work/商品任务/主片交付
```

把获准素材和 UTF-8 SRT 放在任务 JSON 同目录或其下，记录实际商品 ID。文件 SHA-256 可用 `Get-FileHash -Algorithm SHA256` 获得。例中的 ID 和哈希为占位。

```json
{
  "production_route": "real_footage_auto_edit",
  "platform": "douyin",
  "site": "CN",
  "publish_product_id": "our-product-id",
  "asset_manifest": [
    {
      "asset_id": "asset-01",
      "path": "footage/demo.mp4",
      "rights": "owned",
      "product_id": "our-product-id",
      "sha256": "<实际哈希小写>"
    }
  ],
  "cuts": [{"source_asset_id": "asset-01", "in_seconds": 0.5, "out_seconds": 3.2}],
  "subtitle_path": "captions.zh.srt"
}
```

TK 印尼用 `platform: tiktok`、`site: ID` 和印尼语字幕。获准素材的 `rights` 可填 `authorized`。时间线按给定区间原速剪辑，默认用留边保全画面。出片为 1080×1920 H.264/AAC，保留原片音轨。交付目录含 `montage.mp4`、`captions.srt`、`edit_decisions.json` 和 `render_receipt.json`，脚本检查源文件哈希、商品归属、合法时段、码流、尺寸和时长。主片与每个钩子分别指定新目录，审片时核开头、原声、商品动作连续性、字幕、画面安全区和单变量。

运行时来源 [Gyan 9.0.2 发布包](https://github.com/GyanD/codexffmpeg/releases/tag/9.0.2) · [固定版 OpenMontage 合成器](https://github.com/OpenMontageInc/OpenMontage/blob/fecb9a1e3cc23ef84de30b272059457a427f16f8/tools/video/video_compose.py)。

产品图路径逐镜补 `reference_image_ids`、场景/镜头运动、产品不可改变项及允许生成范围，再映射到选定引擎的参数。需要保持外形、颜色、标志、包装数量与产品比例，生成后逐镜核对；失败镜头重做或删掉，不把漂移当同款。

### 重点帧与字幕复核

编导在原有成片任务中可选填 `review_points`。使用同一条成片时间线，按时间升序写 1–8 处需要复核的画面。每处标记 ID、成片秒数和镜头用途。用途可为整体 `overview`、细节 `detail`、使用 `use`、主展示 `hero`、其他 `other`。选实际需要的检查点即可，缺少可证实的使用场景时省略该项。下面的字段可加入上方示例的任务 JSON。

```json
"review_points": [
  {"id": "opening", "time_seconds": 0.4, "role": "overview"},
  {"id": "finish", "time_seconds": 2.0, "role": "hero"}
]
```

同一任务的 ID 忽略大小写须唯一，使用字母、数字、短横线或下划线，以字母或数字开头，最多 32 个字符。成片秒数须落在实际时间线范围内。启用后会校验 UTF-8 SRT 内每段字幕的时长、次序、重叠及越界；渲染成功后从实际 MP4 提取 JPEG，并保存 `review.json` 及 `review_frames/`。回执含请求取帧时间、计划对应的原片和源时点、源片和取帧哈希。切点附近按实际帧率取可解码帧，复核时同步查看回执和实际画面。

逐点查看镜头主体、唯一视觉重点、字幕有没有遮挡商品或被截断，逐段检查运动方向、切换节奏和口播是否清楚。标注材质、结构、安装或使用方法前，先核原片或已批准商品证据。使用外部素材时保留原始来源、具体许可、署名要求、适用渠道及是否允许商用和改编；授权未核实的素材不进入成片。配乐节奏服从可理解的口播和真实动作。抽帧结果需结合整段回看，无需新增客户操作。

## 真实物性与创意展示

捏压、回弹、拉伸、清洗等能够影响商品质量判断的段落，优先使用能回溯的原速实拍。AI生成的动作属于创意表达，不能作为实测性能或真实材质的证据。基于静态图没有确认的填充物、透明剖面、安全检测、适龄或使用效果，不写入生成要求和确定性文案。

原来的连续演示/真实首拆脚本不能直接改成AI伪实拍：实拍路保留相应原片；产品图路则重编为有事实支持的外观、场景或镜头展示。无需为了每条脚本重拍，有现成合适实拍素材即可走混剪；只有缺镜才列补拍项。

## 自动混剪的最小验收

复用现有本地媒体工具，按真实授权素材独立验收此路径。

1. 用一件已核身份商品的我方/获准实拍素材，建立素材表和事实卡。
2. 编导把一个主稿转成能指向真实文件与入出点的时间线；首镜和片尾CTA都有对应素材。
3. 输出至少一条完整竖版MP4及字幕文件，保留时间线和源素材映射；另做至少3个完整钩子版本。
4. 检查解码/时长/声画同步/字幕可读/商品一致/原速连续段和空镜；不能只用“FFmpeg退出0”签质量通过。
5. 确认改变的是约定的单一变量，保留版本和待测指标。未发布不填效果数据。

## 产品图生成的最小验收

沿用已实跑的 MuseCanvas 图生工作流和 OpenMontage 渲染链路。执行新任务前确认素材授权、实际可用连接和调用范围。

1. 选择身份明确的商品原图及事实卡，先制作四宫格三视图。将推定的侧面和背面与原图可见事实分开标注。
2. 按脚本生成若干真实视频镜头，记录引擎/版本、输入图、提示词、参数、任务结果与成本回执。
3. 逐镜检查首、中、尾的外观、颜色、材质、标志、数量、比例与运动。按站点核人物场景、原语口播与字幕，核各条配乐差异、口播相对响度及声画时点。
4. 交完整MP4、字幕、镜头来源与质检记录，实际看成片后验收。只交提示词、静态图或成功任务ID不算自动成片完成。

## 当前接入与下一步

已实跑的语音能力分为 Large-v3-turbo 本机 ASR、Muse Video 同期语音样本和 CosyVoice 3 本机普通话重配。同期样本沿用 Muse Video，MuseTalk 未在本轮所用画布中验收。独立离线图生与网页客户端仍待验证。

实拍路径等待我方或获准的同商品视频，图生路径按[真实失败回归验收清单](真实失败回归验收清单.md)回归挂件保真、市场语言与音轨。网页与本地助手是后续产品方向。ASR、TTS、图生和渲染分别记录部署位置、素材处理范围与客户端验收。
